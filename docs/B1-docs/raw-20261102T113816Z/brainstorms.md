# Brainstorms: raw 副本门禁的观测可靠性

## 1. 事实基线（先分清“违规”与“抖动”）

| 观察 | 证据 |
|---|---|
| 同一 raw、同一内容，门禁三次运行结果不同 | `ok=True` → `ok=False(github:error)` → `ok=True` |
| 平台读取本身不稳定 | `gh repo view --json nameWithOwner` 连测 10 次，失败 3 次（出口代理间歇 502） |
| 两个平台副本都存在且内容一致 | GitHub #4122 与 Gitee IKSEPT 均可读到；`discover_raw_replicas` 两次直接调用均返回两个 `ok` |
| 规范要求“不可达一律阻塞” | `docs/B2-docs/platform/raw-replica-reconciliation/raw-20260725T030511Z/prd.md` Invariants |

因此本次拦截**不是违规**：内容没有分歧，也没有缺副本。它是**观测层抖动被当成了不可用事实**。

## 2. 问题重述

现有实现把三种不同的东西压成同一个 `status != "ok"`：

1. `missing` —— 平台可读，确实没有这条副本（事实，必须阻塞）
2. `unknown` —— 平台读不到（无知，不是事实）
3. `diverged` —— 两个可读副本内容不同（事实，必须阻塞）

第 2 类被当作第 1 类处理，于是网络抖动等价于内容违规。更坏的是：**没有重试**，所以一次 502 就足以让门禁变色。

## 3. 三个 Option

### Option A：只加重试

- 做法：在 `discover_raw_replicas` 外层加 3 次重试，失败仍记 `error`。
- 优点：改动最小，不动 receipt 契约，现有测试全绿。
- 缺点：重试不能消除持续不可用；一旦某平台真的宕机一天，整条生命周期仍然停摆，且**没有任何地方记着“这台机器上还有一条副本没对齐”**。抖动概率从 30% 降到约 3%，但没有把“未知”变成可管理的状态。

### Option B：三态观测 + 默认不变 + 可选降级 + 债账本（选中）

- 做法：
  1. adapter 区分 `ok / missing / unknown`，transport 异常先重试（3 次，0.4s/1.2s 退避），仍失败才记 `unknown`，并保留 `reason`。
  2. `reconcile` 把 `unknown` 放进 `degraded`，**默认仍然阻塞**（规范不变）；新增 `allow_degraded` 开关，只有显式开启才放行。
  3. receipt 增加 `decision`（`allow` / `allow_degraded` / `block`）与 `debt`（平台 + 原因）。
  4. 调用方 `wt-create` 以 `allow_degraded` 调用，并把 `debt` 写进本机账本 `freely.db` 之外的 `.freely/state/sync-debt.json`。
- 优点：事实类诊断（missing / ambiguous / diverged）**行为完全不变**；只把“读不到”从“事实”降级为“待对账”。默认语义不动，浏览器测试与既有用例不受影响。债账本让“一个平台先成功”变成有主、有龄期的临时状态，而不是静默成功。
- 缺点：`wt-create` 的严格性确实下降了一格（从“全平台可读”降到“至少一个平台可读且本地可核对”）。必须靠账本与后续对账补回来，否则就是真正的偷懒。

### Option C：至少一个平台成功即通过

- 做法：`ok = any(replica.status == "ok")`。
- 否决理由：
  - 两个可读副本内容分歧时也会通过（`diverged` 与 `unknown` 被一起放过），这是把“一致性门禁”改成“可用性门禁”。
  - 没有任何补账机制，另一个平台会**永久**停在旧状态，而没人知道。
  - 它回答的是“能不能干活”，不是“两边是不是一致”。freely 的门禁回答的是后者。

## 4. 决策

选 **Option B**。理由不是“想少被拦”，而是：

- 门禁的价值来自**可信**。同一份内容 30% 报红，会让所有人学会“重跑到绿”，这才是真正的门禁失效。
- “未知”应当被降级为**可管理的债**，而不是被伪装成事实。债有平台、有原因、有龄期，可以被 `issue-sync` 或 scan 重放；伪装的 `error` 什么也留不下。
- 事实仍然阻塞：缺副本、重复匹配、内容分歧三条一条都没放宽。

## 5. 不做什么

- 不引入“多数票/quorum”。两个平台时多数等于全体；三个平台时多数会让一个平台永久静默落后。正确的放松维度是**时间（债）**，不是**数量**。
- 不改 `close` 的全平台语义（`close-multi` 仍然要求每个平台都 `closed`）。终局动作不降级。
- 不让 gate 写磁盘（receipt 仍只读）；记账由调用方完成。

## 6. 风险

| 风险 | 缓解 |
|---|---|
| 债被写下但永不偿还 | `sync-debt list` 输出龄期；下一轮 `issue-sync reconcile` 消费账本 |
| `unknown` 被滥用成“什么都放行” | `missing` / `diverged` 仍阻塞；`allow_degraded` 只在显式传参时生效；默认 gate 行为不变 |
| 重试把慢平台拖成整体超时 | 重试上限 3 次、退避合计 ≤ 1.6s；单次调用仍受原 timeout 约束 |

## 7. 待验证

- 持续不可用（真宕机）时，`wt-create` 是否在**至少一个**平台可读时仍能推进，且账本有记录。
- 两个平台都读不到时是否仍然阻塞（`baseline is None` → block）。这是 A/B 之外唯一新增的“全盲”分支。
