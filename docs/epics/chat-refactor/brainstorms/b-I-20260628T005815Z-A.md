### 风险排序
1. **高**：freely 主脚本改动（~20K 行历史债务），容易引入回归
2. **高**：agent-id.env 格式兼容（新增 discuss 条目，不破坏现有 parser）
3. **中**：平台 Discussions API 差异（GitHub vs GitCode，Gitee跳过）
4. **中**：旧 chat 入口废弃后 CLI 用户提示
5. **低**：scan chat_inbox 删除（依赖已明确）

### 实现顺序
阶段一（comment）→ 阶段二（discuss）→ 阶段三（discuss-execution skill）→ 阶段四（archive skill）→ 阶段五（门禁）→ 阶段六（拆除 old chat）→ 阶段七（边界文档）

## 替代方案评估

### 方案 A: 全改自由脚本
直接在 freely 里加所有逻辑，不拆模块。
- 拒绝：freely 太大，违反文件规模约束

### 方案 B: adapter 封装 + skill 独立
platform-adapter 封装平台操作，skill 独立为 .md 文件，freely 只做命令路由。
- 采纳：与现有架构一致，skill 是 AI CLI 无关的描述层

### 方案 C: 新建独立脚本文件
每个命令独立一个 bash 脚本（bin/comment、bin/discuss）。
- 拒绝：分散入口，与 freely 子命令模式不一致
