# I-20260625T050000Z-A: Move git pull in pr-create-guarded after all gates pass

## Background

`pr-create-guarded` currently runs `git pull origin develop` at Step 1, before
any gate checks. Every time a gate fails and the user retries, the pull runs
again — a wasted network round-trip since the remote hasn't changed.

## Scope

Move the `git pull origin develop` from Step 1 to Step 3 (just before push),
after all gates have passed. Any gate failure exits early without any network
call.

## Changes

- `docs/system/workspace/scripts/worktree/pr-create-guarded`: Moved `git pull origin develop`
  from Step 1 to Step 3 (between gate-passed marker and push)

## Implementation Decision Note

**Decision**: Move the pull to Step 3, after all gates pass but before push.
The pull and push are now adjacent, forming a tight fetch-and-push sequence.

**Rationale**: Gates (clean, phase_state, dry-run, IBM governance, pretests) are
all local checks that don't need the remote. Only push needs up-to-date remote
state. Moving pull to Step 3 eliminates redundant pulls on gate failure retries.

**Trade-offs**: If someone gate-skips (e.g., `FREELY_SKIP_IBM_GATE=1`) and the
remote has diverged significantly, the pull at Step 3 could introduce conflicts.
This is acceptable — the same conflict risk exists with pull-at-Step-1, just
manifested differently.
