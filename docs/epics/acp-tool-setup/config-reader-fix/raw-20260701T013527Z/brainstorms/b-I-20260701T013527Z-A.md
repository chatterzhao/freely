# B2 Brainstorm: get_config → bash indirect expansion

## Input
- Candidate: C-20260701T013527Z-A (status=promoted)
- Acceptance criteria: daemon 启动不再报 get_config 错误，ACP bridge 可从 config.toml 读取路径

## Implementation Analysis

### 当前代码
```bash
local _config_path; _config_path="$(get_config "$_config_key" "")"
```

### 问题
`get_config` 函数未在脚本中定义。该位置在 `_ensure_acp_bridge_running()` 内，daemon 启动时执行。

### 修复
```bash
local _config_path; _config_path="${!_config_key:-}"
```

### 理由
- `load_config` 已通过 `source_config → toml2env` 将所有 config.toml 值导出为环境变量
- bash indirect expansion (`${!varname}`) 是标准做法
- 零额外 IO，无新函数定义

## 替代方案评估
- **定义 get_config 函数**: 需要重复读取和解析 config.toml，增加维护负担 ❌
- **使用 _read_config_value**: 该函数是嵌套函数，不在当前作用域，且依赖 Python 子进程，开销大 ❌

## Decision: `${!_config_key:-}`
最简洁、最高效、与现有 load_config 机制完全一致。
