# 研究：EvoMap 生态与 Freely 升华

## Context

理解 EvoMap 核心概念：

| 概念 | 定位 | 类比 |
|------|------|------|
| Gene | 可复用策略模板 | "解题思路" |
| Capsule | 验证通过的修复方案 | "正确答案" |
| Registry | 能力注册局 | "经验数据库" |
| GDI 评分 | 全局期望度指数 | "答案质量分" |
| A2A 协议 | 能力传播 | "经验分享" |

**与 MCP/Skill 的层级关系**：
```
MCP  → What（有什么工具）
Skill → How + What（怎么做）
GEP  → Why + How + What（为什么有效）
```

## Freely 现有沉淀

| 现有资产 | 对应 EvoMap 概念 | 升华方向 |
|----------|------------------|----------|
| 品味.md | Skill 级别 | 增加"Why"验证记录 |
| 验收标准 | 无对应 | 可发展为 Capsule |
| 进度文档 | 无对应 | 可积累为项目知识图谱 |
| 宪法 | Ring 0/1 | 增加审计追踪 |

## 升华方向

### 方向 1：品味.md → 进化胶囊化

**当前**：
```
品味.md = 静态约束规则
```

**升华后**：
```
品味.md + 验证记录 = 进化胶囊

{
  "gene": "品味.md 的核心约束",
  "capsule": "实际使用验证结果",
  "gdi": "方案质量评分",
  "env_fingerprint": "验证环境"
}
```

**价值**：品味不只是"规定"，而是经过验证的"有效经验"

### 方向 2：验收标准 → 能力注册

**当前**：
```
Story 验收标准 = 当次使用
```

**升华后**：
```
验收标准 + 使用效果 = 可复用能力资产

- 积累哪些验收标准经常使用
- 评估哪些标准有效/无效
- 形成项目专属的"验收模式库"
```

### 方向 3：进度文档 → 知识图谱

**当前**：
```
进度文档 = 执行记录
```

**升华后**：
```
进度文档 + 语义关联 = 项目知识图谱

- Issue 之间的依赖关系
- 决策的历史背景
- 技术选型的理由链
```

### 方向 4：外部工具调用 → 进化网络

**当前**：
```
外部工具 = 被调用执行单元
```

**升华后**：
```
外部工具调用结果 → 反馈到进化网络

- 记录哪些工具调用成功/失败
- 评估不同场景下的工具效果
- 形成工具选型建议
```

## 具体可落地的机制

### 1. 品味验证记录

```bash
# 每次使用外部工具时
记录:
  - 传入的品味.md 内容
  - 执行结果（成功/失败）
  - 效果评分
  - 环境信息

生成:
  - 品味验证报告
  - 有效/无效约束标记
```

### 2. 验收模式库

```bash
# Story 验收标准使用后
记录:
  - 原始验收标准
  - 实现难度
  - 测试覆盖度
  - 是否满足需求

生成:
  - 常见验收模式
  - 有效标准模板
```

### 3. 决策链追踪

```bash
# 关键决策点
记录:
  - 问题描述
  - 可选方案
  - 最终选择
  - 选择理由
  - 后续效果

生成:
  - 决策知识图谱
  - 可追溯的技术选型
```

### 4. 工具效果评估

```bash
# 工具调用后
记录:
  - 工具名称与版本
  - 调用参数
  - 执行时长
  - 输出质量评分

生成:
  - 工具效果排行榜
  - 场景-工具匹配建议
```

## 与 EvoMap 的对接策略

### 短期（内建能力）

| 能力 | 实现方式 | 价值 |
|------|----------|------|
| 品味验证记录 | 数据库 + 分析 | 量化品味有效性 |
| 验收模式库 | 文档积累 + 提取 | 复用经验 |
| 决策链追踪 | 进度文档增强 | 可追溯 |
| 工具效果评估 | 日志 + 评分 | 优化调用 |

### 中期（生态连接）

| 能力 | 实现方式 | 价值 |
|------|----------|------|
| A2A 协议支持 | 可选接入 | 与其他 Agent 协作 |
| 能力注册 | 标准化输出 | 经验可分享 |
| GDI 评分接入 | 外部评估 | 质量量化 |

### 长期（自我进化）

| 能力 | 实现方式 | 价值 |
|------|----------|------|
| 基于历史的建议 | ML + 历史数据 | 智能推荐 |
| 自适应流程 | 动态调整 | 效率提升 |
| 跨项目知识迁移 | 知识图谱 | 经验复用 |

## 核心升华点

**不是直接用 EvoMap，而是借鉴其思想**：

| EvoMap 概念 | Freely 借鉴 | 落地形态 |
|-------------|-------------|----------|
| 进化胶囊 | 品味验证 | 约束 + 验证结果 |
| GDI 评分 | 效果评估 | 质量量化 |
| 知识图谱 | 决策追踪 | 可追溯决策链 |
| A2A 协议 | 工具网络 | 可扩展接入 |
| 优胜劣汰 | 有效/无效标记 | 持续优化 |

## 结论

EvoMap 给我们的最大启发是：

> **不只是执行任务，还要积累"为什么有效"的经验**

Freely 可以借鉴这个思路：
1. **不只是约束（品味.md），还要验证约束是否有效**
2. **不只是记录（进度文档），还要形成可复用的知识**
3. **不只是调用工具，还要评估工具效果**

这样 Freely 就从"执行器"升级为"进化系统"——每一次运行都在积累经验，每一次循环都在优化。
