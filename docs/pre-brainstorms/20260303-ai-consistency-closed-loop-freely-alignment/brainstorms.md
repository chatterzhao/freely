# 研究：AI 一致性闭环与 Freely 工具职责对齐

## Context

- 研究时间：2026-03-03
- 研究对象：
  - Freely 项目意图：`docs/PROJECT_INTENT.md`
  - Freely 宪法：`docs/CONSTITUTION.md`
  - 外部文章：<https://www.wanghuan.ai/blog/ai-consistency-closed-loop>
- 研究前提：
  - Freely 的身份是“用 AI 自动开发项目的工程工具”，不是单篇方法论容器。
  - 任何外部观点都必须先通过“工具职责过滤”，再决定是否进入核心能力。

## 一、先立身份：Freely 的职责边界

### 应该负责（In）

1. 让 AI 在项目级闭环中稳定运行：Issue -> 文档 -> 开发 -> 验收 -> 续接。
2. 把工程质量要求变成自动化门禁，而不是人工记忆。
3. 提供可追溯、可恢复、可审计的执行过程。
4. 让“人类意图 + 宪法约束”在自动模式下持续生效。

### 不应该负责（Out）

1. 追求某种单一技术形态（如只做 MCP 平台）。
2. 依赖“高手手感”保证质量。
3. 把研究观点直接当实现，缺少可执行契约和验收定义。

## 二、外部文章的可采纳抽象（对工具有用的部分）

文章可沉淀为 6 个可工程化机制：

1. Ring 分层（上下文权威层级）
2. SSOT 阶梯（冲突时按权威回溯）
3. 文档解压缩（执行输入需自包含）
4. 测试围栏（人定验收边界，AI 执行）
5. 独立监理（执行与评审上下文隔离）
6. 前置纠偏（实施前发现偏移优先于事后 debug）

这些机制不是“风格建议”，而是可转成自动化门禁的质量基元。

## 三、与 Freely 理念/宪法的对齐评估

### 已对齐（基础已具备）

1. 闭环目标一致：项目意图明确持续自动循环。
2. 文档优先一致：宪法明确文档驱动与可追溯。
3. 子代理方向一致：宪法已要求委托规划、并行、回退与记录。
4. 恢复原则一致：宪法将恢复定义为强制能力。

### 未闭合（需要补成产品能力）

1. 没有显式 Ring/权威层规则（目前散落在意图和宪法中）。
2. 没有统一 SSOT 冲突决议流程（何时修代码，何时修文档）。
3. 没有“自包含交付”的硬性验收模板。
4. 没有独立监理的输入输出契约和通过标准。
5. 没有把“一致性预检”作为进入 dev-loop 的强制关口。

## 四、落地形态：以 Skill + Gate 为核心，不以接口形态为核心

研究结论：如果目标是“AI 自动且质量稳定”，核心不是先选 MCP/Slash，而是先把质量约束产品化。

### 4.1 共性 Skill（建议作为平台内置能力）

1. `intent-constitution-loader`
- 加载并固化 Ring 0/Ring 1 上下文（宪法与项目意图）。

2. `acceptance-contract-builder`
- 从 Story 生成可执行验收合同（验收项、边界、失败条件）。

3. `integration-first-test-planner`
- 先定义集成验收测试，再允许实现步骤进入开发。

4. `ssot-conflict-resolver`
- 在 PRD/设计/代码冲突时输出“回溯修正决议”。

5. `self-contained-delivery-checker`
- 校验执行文档是否自包含，是否存在危险跨文档依赖。

6. `independent-auditor`
- 在独立上下文完成一致性审查并给出放行/驳回。

### 4.2 自动循环中的强制门禁（Gate）

建议将以下流程固定为自动模式硬门禁：

1. Ring 对齐门：未识别 Ring 0/1 不得开始执行。
2. 验收合同门：无验收合同不得实现。
3. 集成测试门：无集成验收测试不得合并。
4. SSOT 一致性门：文档-实现冲突未决不得推进。
5. 独立监理门：未通过独立审查不得宣告完成。

## 五、对“工具职责”的直接回答

Freely 应该做的是：

1. 把“品味/灵魂/原则”转成可机器执行的 Skill 和 Gate。
2. 在 auto 模式下强制这些 Gate 逐轮生效。
3. 让质量来自流程约束，而不是来自某次 prompt 运气。

换句话说：文章给的是“方法论语言”，Freely 要产出的是“自动化质量控制系统”。

## 六、后续研究与实现建议

1. 先出《Ring 与 SSOT 规则》规范草案（作为系统提示词与 Skill 输入源）。
2. 再出《验收合同模板》与《集成优先测试模板》。
3. 最后出《独立监理协议》并接入 auto-loop 的放行逻辑。
