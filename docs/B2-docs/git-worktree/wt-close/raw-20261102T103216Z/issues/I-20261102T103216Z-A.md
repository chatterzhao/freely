# I-20261102T103216Z-A: 受控调用方显式标记

## 背景

`wt-create` 创建受控分支、`wt-close` 删除远程分支时，hook 用 `ps` 遍历父进程识别调用方。沙箱禁用 `ps` 后识别恒失败，两个封装命令都被自己的门禁拦住，形成鸡生蛋。

## 根因

- `.githooks/{reference-transaction,pre-push}` 只是包装层，真实逻辑在 `docs/system/workspace/hooks/`。
- 两个 hook 的 `_caller_is_wt_create` / 删除分支判定都只依赖 `ps -o comm=/args=/ppid=`，没有第二条授权通道。

## 目标

- 封装命令在调用 git 前设置显式标记；hook 先看标记，再看 `ps`。
- 直接 `git worktree add -b` 与直接 `git push --delete` 仍被拦截。

## 非目标

- 不改合并门禁、不放开 develop/main 保护。
- 不做跨平台进程探测重写。

## 验收

见 `verification/pre-tests.md` AT-001..AT-004。
