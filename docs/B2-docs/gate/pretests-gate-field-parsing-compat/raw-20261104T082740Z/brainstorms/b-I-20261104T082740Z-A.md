## 方案评估

1. **引号剥离的条件**：必须同时满足「首尾是同一种引号」「内部不含该引号」。否则 `` `a` 与 `b` `` 会被当成整体包裹值而丢掉中间的反引号，或 `--output` 指向 `/` 时拒绝 的首尾反引号被误剥。加 `if value[0] not in inner` 守护即可同时满足 #3957 的单值包裹与本次的多段行内代码。
2. **空值语义不能一刀切**：`has_blocker_taxonomy()` 历史上用两条正则分别覆盖「有值」与「空值行」，因此统一后用 `present`（而非 `value`）；`issue_is_follow_on()` 与 `derive_tasks_path()` 历史上要求值非空，因此用 `present and value`；`parse_fields()` 历史上只收录有值键，因此也是 `present and value`。
3. **`re.escape(key)`**：`parse_fields` 的键含 `red-green-status`，原本直接插入正则未转义。统一函数统一 `re.escape`，避免键名里的正则元字符造成意外匹配。
4. **`[ \t]*` 与 `(.*)` 组合**：`[ \t]*` 吃掉冒号后的空白，`(.*)` 吃剩余全部；再 `.strip()` 去掉行尾空白。这样 `- requirement:` 空行得到 `value=""`，`present=True`，不会跨到下一行。
5. **不做文档格式迁移**：把治理文档改成 YAML 会牵动 200+ 份已有 pre-tests.md 与全部 skill 模板，远超本 issue 边界。

## 测试策略

- `unit` 组：按 `<<'PY'\n` / `\nPY` 切出内嵌 Python，再按 `if issue_arg:` 截断只保留定义区，`exec` 后直接调用被测函数。这样不依赖 git 仓库、不触网、毫秒级完成，能精确断言 14 个键与 4 种引号。
- `e2e` 组：`mktemp` 隔离仓库，复制 `bin/pretests-gate` shim 与 `scripts/quality/pretests-gate` 真源，构造含行内代码反引号的 `requirement` 与 `required_evidence`、四章节、Acceptance Items、tasks.md、证据文件与 review 文件，运行真实门禁断言退出码 0 且无字段缺失报错。这一组是「真实 git 仓库」而非 mock。
