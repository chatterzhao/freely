## 根因

投影是「被别处执行或读取的真源副本」，但没有任何机制证明副本仍与真源一致：
`.githooks/` 积累了 4 个死 `.sh` 副本 + 2 个残留备份；`post-checkout` 干脆是 105 行
业务实现而非 wrapper；`deploy-skills` 三处 `cp -r` 不留 hash；AGENTS 生成器与模板
引用了 3 个**根本不存在**的 skill 名。

## 修复方案

1. 删 6 个非 wrapper 文件；`post-checkout` 迁到 `workspace/hooks/post-checkout.sh`
   （自解析仓库根，不依赖调用方 cwd），`.githooks/post-checkout` 变 11 行 wrapper。
2. 修生成器 6 处 + 模板 3 处幽灵 skill 名 → 真实的
   `freely-workflow-guarded-execution` 与 RED/dev/GREEN 三阶段；`--skill <ghost>` 改 `--kind fix|feature`。
3. 新增 `quality/projection_verify.py`：`record` 生成 lock，`verify` 逐项校验。
   **copy 型**比字节 hash；**delegate 型**pin 真源 hash 并检查 wrapper 仍 exec 它。
   agents 型校验「引用的 skill 名都存在」。
4. `projection.lock` 覆盖 hooks/bin/agents（相对路径，可提交）；skills 投影写
   machine-local lock（$HOME 绝对路径不入库），由 `deploy-skills` 部署后自动记录。
5. `bin/projections` 投影 + runtime 内联 `exec` 分派；AT 进 `CORE`/`CI_CORE`；
   `epic-gate` 注册 `projection-consistency` story。

## 验收标准

- RED：develop `27e91e50c` + 最终版 AT-001 → `1 ok / 19 failed`（唯一 ok 是「8 个 wrapper 都在」的基线事实）。
- GREEN：AT-001 `20 ok / 0 failed`；`freely projections verify` → `ok (63 projections consistent)`。
- GREEN：unit 17 文件 111 断言；`test-all --ci` 21/0；epics 17/216。
- GREEN：`check-runtime-size` ok（27158/27158，**未上调预算**）；`check-bin-projection` ok（100 入口）。
- 不退化：7 个既有 AT 全绿（R27 21、R28 21、R28.5 18、R29 16、R30 17、R31 16、R32 16）。
