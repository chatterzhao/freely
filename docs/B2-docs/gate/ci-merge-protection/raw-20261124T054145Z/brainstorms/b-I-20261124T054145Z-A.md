## 测试设计（端到端优先）

- 端到端（AT-003）：直接读 GitHub 分支保护 API，证明 develop 从 404 翻转为 enforce_admins=true + required check。这是用户可见的最终行为。

- 单元：AT-001 内静态断言 workflow permissions 与 pr-merge-guarded 无自签 fallback。

## 方案评估

- 单一语义：check 名 `governance/pr-merge-guard` 的创建者只能是 CI，置 success 者只能是治理门禁，强制者是分支保护；三方职责不重叠。
- fail-closed：check 缺失 / API 失败一律非零退出，禁止 `|| true` 吞错、禁止自造 check。
- 兼容性：保留 check 名与 verify job，避免影响既有分支保护规则（一旦配置）与其他依赖该 check 的工具。

## 结论

采用 Option C，按 tasks.md T1–T6 执行。RED 用 develop 基线真实复现（缺陷客观存在），不使用 mock 通过。
