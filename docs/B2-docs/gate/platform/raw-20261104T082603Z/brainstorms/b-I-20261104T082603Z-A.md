# Design Brainstorm: I-20261104T082603Z-A

## 决策 1：校验用「纯 transition 预演」，而不是复制一份终态判断

`raw_metadata_contract.transition()` 是纯函数：输入 metadata + event，返回新 metadata 或抛 `MetadataValidationError`。把 `platform_closed` 事件先跑一遍，就得到三件事：① 终态校验（唯一实现，不重复）；② 目标结果（可直接回写，不需要第二次解析）；③ 失败原因（`requires terminal raw phase`）。bash 侧再写一遍 `[[ $phase == absorbed || $phase == dropped ]]` 会立刻产生第二份真源，重犯 #4154 的病。

## 决策 2：平台写之前必须已经「决定好本地状态」

顺序改为：预演 → （失败即返回，平台零调用）→ 调 adapter 关闭 → 全成功才 `write_issue(预演结果)`。这样「平台已关、本地未关」在结构上不可能再发生：本地结论在写平台之前就已经算出并且是可写的。

## 决策 3：拒绝伪回滚

平台关闭失败后不尝试「把已关闭的平台重开」。issue 重开会留下关闭/重开的评论与状态历史，且在 Gitee 侧需要额外 API 与权限。正确做法是把「已关一半」如实上报（rc 3 + 逐平台 status），依靠关闭的幂等性重跑自愈。

## 决策 4：退出码三态贯穿关闭通道

`create-issue` 在 R11 已是 0/3/1，关闭通道仍是二态 `all closed else 1`。统一为：0 全关、3 部分、1 全失败，由 `_close_exit_code()` 一处实现，`close-multi` 与 `close-raw` 共用，`close_platforms` 逐值上抛，`cmd_close` 把 3 原样传出（不再压成 1）。

## 决策 5：非严格路径同样禁止自证

非严格路径（I-* 等没有 `schema_version: 1` 的对象）此前逐平台 `|| echo FAILED` 后再无条件写 `platform_state=closed`。改为累计每个平台的结果：全部成功才写 `closed`；部分成功 rc 3；全部失败 rc 1；失败时 `platform_state` 保持原值，让 batch 扫描仍能看到它是待同步。

## 决策 6：`wt-close` 的只读关闭不改

`wt-close` 里 `if _close_issue_platforms_readonly ...; then` 的语义是「关成功就继续、否则打警告」，rc 从 1 变 3 仍走 else 分支，行为不变，因此不改 `wt-close`。这点在 IDN 里显式记录，避免被误判为遗漏。

## 退化审计方法

1. `git archive develop -- bin docs` 出基线快照，把**最终版** AT-001 拷进去 → RED；
2. 工位同断言 → GREEN；
3. 相关回归（write-channel / raw-metadata / reconciliation / parity / handler-probe）工位与基线逐一对比退出码；
4. 真实仓库只读核验：非终态 raw 关闭必须零平台调用。

## 被否决

bash 侧重复终态判断；伪回滚已关闭平台；非终态允许关闭（issue 方案 2）；夹带 `update` / `comment` 通道与入口层收口（#4166）。
