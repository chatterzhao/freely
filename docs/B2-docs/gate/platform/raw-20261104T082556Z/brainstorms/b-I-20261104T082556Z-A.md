# Design Brainstorm: I-20261104T082556Z-A

## 决策 1：一个解析器，而不是给 promote 打补丁

`cmd_create/update/comment/close/status` 五处都是同一个 B1-only 假设。只改 promote 会让 update/comment 对 I-* 继续必然失败，等于把 bug 留在原地。统一为 `_issue_file_for`，B1 精确路径优先（与旧行为等价），再退到 B2。

## 决策 2：歧义必须 fail-closed

`find -name "${i_id}*.md" -print -quit` 在有多份匹配时**随机**返回一份。改为收集全部匹配：0 份 → rc 1；>1 份 → rc 2 并把候选路径全部打印。promote 是写平台的操作，猜错就是往错误对象上建单。

## 决策 3：`platform_state` 是 raw 字段

`cmd_create` 成功后会写 `platform_state=open`。linked I-* 文档的 frontmatter 里没有这个键，无条件写入会静默改变它的 schema（后续 `validate` 可能因此失败）。用 `_fm_has_key` 守卫，只对已声明该字段的文档写值。

## 决策 4：不复制文档，不建双真相源

复制/软链 B2 文档到 B1 能让旧代码跑通，但会制造两个副本：close/batch 读哪份？最终一定分叉。路径解析收口在读取侧。

## 退化审计方法

1. `git archive develop -- bin docs` 基线快照 + 最终版 AT-001 → RED `4 ok / 12 failed`；
2. 工位同断言 → GREEN `16 ok / 0 failed`；
3. 7 个相关回归（写通道、关闭路径、test-gate、raw-metadata、reconciliation、parity、wt-close）与基线逐一对比退出码；
4. 真机：本轮 R13 自己的 absorb 将走修好的 `issue-sync promote`。

## 被否决

只改 promote；复制到 B1；`find | head -1`。
