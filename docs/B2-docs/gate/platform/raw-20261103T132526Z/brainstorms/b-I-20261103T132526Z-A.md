# Design Brainstorm: I-20261103T132526Z-A

## 决策 1：写原语换薄封装，而不是给旧签名打补丁

旧 `_gitee_call <method> <json>` 与 `gitee-issue.py`（argparse 子命令 + 具名 flag）根本不同构。在 bash 里把 JSON 拆成 flag 是第二层字符串拼装，错一次又是静默失败。改为 `_gitee_cli <action> [flags]` + 四个薄封装，调用点直接传参数。

## 决策 2：失败不兜底

`|| echo '{"ok":false}'` 把「退出码 2」变成「合法空结果」，调用方只能看到空 id，然后当成「没创建成功但也没报错」。删除兜底后，失败就是非零退出，调用方按 rc 判断。

## 决策 3：token 只有一处权威

`bin/issue-sync` 里 4 处 `-n "${GITEE_TOKEN:-}"` 从未被赋值，导致 Gitee 通道整体跳过而脚本继续宣布成功。token 的权威来源是 `gitee-issue.py` 的 `freely_user_env`（支持环境变量与配置文件），bash 侧不再重复判断。

## 决策 4：`platform_state` 是对全部平台的断言

`platform_state` 被 batch 扫描用来「跳过已同步」，写错就是永久分叉。因此：任一平台失败 → 不写；成功的平台 id 仍然先落 frontmatter（下次重跑 dedup 生效，不会重复建单）→ 退出 3。

## 决策 5：探测要报因，不要报「不支持」

`detect()` 返回 bool 的四合一让「PATH 里没有 gh」显示为「unsupported platform: github」。新增 `detect_reason()` 返回 `(ok, reason)`，四类原因分别可读；`_unavailable_error()` 把原因拼进 error 文本。`detect()` 保留（抽象契约不变），内部委托 `detect_reason()`。

## 决策 6：退出码 0/3/1 贯穿

adapter `create-issue` 与 `freely feedback` 统一：0 全部成功、3 部分成功、1 全部失败。部分成功时把已创建平台的 id 交给调用方（adapter 已在落盘 frontmatter 时写入），并提示重跑 `issue-sync create` 自愈。

## 退化审计方法

1. `git archive HEAD -- bin docs` 出基线快照，把**最终版** AT-001 拷进去 → RED（15 失败）；
2. 工位同断言 → GREEN（22 ok）；
3. 相关回归（platform parity / reconciliation / adapter）工位与基线逐一对比退出码与输出；
4. 真实仓库只读核验 `_gitee_repo` 与 adapter 探测输出。

## 被否决

保留旧 JSON 签名（两层拼装）；bash 侧读 token（双权威）；文本 grep 判状态（行位置不稳）；夹带 #4184 关闭路径 / #4154 常量收口 / #4166 入口收口。
