## 3. 充分性

- 行为用例驱动的是**真实** `bin/issue-sync`（借 `BASH_SOURCE` 守卫作为库加载、`ROOT_DIR` 可覆盖），不是复制逻辑；断言对象是退出码、frontmatter 实际内容、被调 CLI 的 argv 形态。
- `_gitee_repo_from_url` 是抽出的纯函数，三种 URL 形态各一条断言，避免「只测了本机那一种」。
- 负面用例齐备：gitee 失败必须非零、partial 必须 3、all-failed 必须 1。
- 静态断言只针对「静默模式」，不绑定实现细节（不要求保留某个函数名）。

## 4. 破坏性变更评估（合并前必查）

- **fail-open 收窄**：三处全部朝更严格方向 —— 写失败不再兜底成空结果、`platform_state` 不再在部分成功时写、探测不再把「环境不通」说成「平台不支持」。
- **是否有删除检查**：无。删除的是 `|| echo` 兜底与 4 处未赋值变量的门禁，不是检查。
- **关闭路径**：`_gh_close` 改为返回真实状态，但调用点加了 `|| echo FAILED` 保持历史「报告后继续」语义 —— **不把部分关闭变成硬中止**，该口径留给 #4184。
- **读通道**：`read_health` / `__degraded__`（#4195）逐字节未改；`close` 严格路径（`_raw_effect close-platforms`）未改。
- **新增的自锁风险**：`cmd_create` 现在会 `exit 3`。它被 `cmd_promote` 调用，部分成功时 promote 会中止 —— 这是期望行为（写通道没修好就不该继续 promote），且已被 AT-001 的 partial 用例覆盖。
- **回归**：9 个相关回归基线对比退出码全一致，5 处差异仅为 unittest 计时行。
