## 实现

- `lifecycle/raw_metadata_contract.py`：可选第 22 字段 `severity`（`SEVERITY_FIELD` / `VALID_SEVERITIES` / `DEFAULT_SEVERITY` / `RAW_METADATA_FIELDS_WITH_SEVERITY` / `resolve_severity()`）；`new_raw_metadata(severity=)` 追加字段；`validate()` 接受 21/22 两种形状并校验取值；`normalize()` 读视图回填 P2。
- `runtime/freely`：`cmd_feedback` 把 severity 传入 frontmatter 构造，并在 `create-issue` 第 4 参传 `kind/raw,phase/proposed,severity/Pn`。
- `sync/platform-adapter.py`：`create_issue(..., labels="")` + CLI 第 5 参；仅在 labels 非空时把第 3 参传给 handler；GitHub `--label`、Gitee `--labels`。
- `bin/issue-sync`：`_labels()` 输出 `severity/Pn`（缺省 P2）；`cmd_scan()` 收集后按 P0→P1→P2 稳定排序并输出 `sev=Pn`。

## 不退化边界

- 严格 21 字段文档仍通过 `validate()`；未批量重写任何历史 raw 文档。
- `create_issue()` 无 labels 时仍以 2 参调用 handler，自定义 handler 与既有调用面不变。
- 关闭路径四段式、副本一致性、test-gate、promote 链路均未改。
