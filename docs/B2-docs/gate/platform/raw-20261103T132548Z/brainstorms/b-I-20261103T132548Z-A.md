# Design Brainstorm: I-20261103T132548Z-A

## 决策 1：证据格式由单一 Python 模块拥有

`test-evidence.py` 同时负责写与验，避免「写的人宽松、读的人宽松」两端漂移。8 字段中最关键的是 `TEST_EXIT_CODE` 与 `EVIDENCE_SHA256`：前者来自真实进程，后者把证据文件绑定到结论。

## 决策 2：只有 `run` 能产出可信结论

`record` 是 agent 自述接口（R12.5 的唯一写入点），保留但不升级为可信来源：它写出的 3 字段格式会被新校验判为缺字段。新 `test-gate run` 在 test 工位真实执行 `bash -c <command>`，把合并输出写成证据文件并记真实 rc。

## 决策 3：门禁 fail-closed，缺 helper 也拒绝

`pretests-retirement-gate` 在原有 freshness 检查之后追加 validate；helper 文件缺失时直接 `pretests_evidence_invalid`，不允许「没装新模块就静默按旧规则放行」。

## 决策 4：白名单 + 显式 known-broken，而不是一次跑全部

500+ 测试里有大量预存红，一次跑全部会让 CI 永久红、信号归零。`bin/test-all` 先跑已验证子集（本地 9 / CI 5 / extended +5），把其余 575 个明确列出为 known-broken / 未 onboarding，留出渐进收口路径。

## 决策 5：CI 只跑纯本地子集

Gitee 与 GitHub 的 job 都跑 `bin/test-all --ci`（5 个纯 Python 单元/契约测试），不依赖 `gh`、remote 或本机安装态，保证干净 checkout 可复现。

## 决策 6：macOS bash 3.2 兼容

本机 bash 3.2 没有 `mapfile`；runner 用 `ls | grep | printf` 的可移植写法，避免 CI（Linux）与本机（macOS）行为分叉。
