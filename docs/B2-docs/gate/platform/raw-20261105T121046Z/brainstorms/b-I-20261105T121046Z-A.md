# Design Brainstorm: I-20261105T121046Z-A

## 决策 1：一个 Python 库，不是散落的三份 shell 判断

安装态的「身份」包括版本来源、文件字节、latest 指向、PATH 链接四件事。让 `freely-package`、`cmd_doctor`、merge followthrough 各自实现必然漂移（R13.5 已因两份评论判定吃过亏）。统一到 `install_state.py`，CLI 只是薄包装。

## 决策 2：hash 清单而不是只比版本号

`FREELY_PACKAGED_FROM` 只能说明「打包时是哪个 commit」，无法发现安装态文件被改/被部分覆盖。`KEY_FILES` 六个入口文件的 sha256 清单让「代码一致」可机器证明；目录内容由这些入口间接覆盖，清单保持可读且打包开销恒定。

## 决策 3：激活必须原子且 fail-closed

`activate()` 先验证版本目录 + `.freely_version` + 清单，再用临时 symlink + `os.replace` 切换；任何失败都在动 `latest` 之前返回。读者只会看到旧或新目标，永远不会看到缺失的 `latest`。

## 决策 4：不覆盖健康的 PATH 链接

当前 `~/.local/bin/freely` 指向项目真源（R5.5 的开发态规避），这是有效的。只在链接悬空或缺失时重建。强行改指向安装态会破坏开发态，属于无谓的破坏性变更。

## 决策 5：合并触发是幂等的 best-effort

合并已提交、无法回滚，所以打包失败只告警并给出修复指令，不把 merge 判失败。`--version auto` 生成分钟级版本号，而幂等判断基于「latest 记录的 HEAD == 当前 HEAD」，重复执行直接退出 0，不产生新版本目录。

## 决策 6：测试完全隔离

行为组用 `tempfile` 建临时 home + 临时 git 项目，仅 import 真实库与跑真实 CLI；不执行真实打包（会写 `~/.freely`），也不改 `~/.local/bin`。静态组绑定接线契约，不绑定内部实现细节。

## 退化审计

1. `git archive develop -- bin docs` 基线快照 + 最终版 AT-001 → RED `2 ok / 21 failed`；
2. 工位同断言 → GREEN `23 ok / 0 failed`；
3. 21 个相关回归（3 个 doctor、3 个 package/parity、15 个写通道/生命周期/门禁）worktree 与基线逐一对比退出码；
4. 真机：合并后 followthrough 自举刷新安装态。

## 被否决

只打印提示不写清单；每次调用 freely 都自动打包；软链项目树替代安装态；无条件清空 `~/.freely/versions/*`；激活时覆盖健康链接。
