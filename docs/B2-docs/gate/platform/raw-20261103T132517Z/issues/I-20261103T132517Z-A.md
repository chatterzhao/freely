## 实现

- `raw_metadata_contract.py`：新增 `extract_bullet_fields` / `validate_issue_text` / `parse_issue_text` / `validate_issue_path`；`read_issue` 把 YAML 异常包装成 `MetadataValidationError`。冲突标记判定要求 `<<<<<<<` 与 `>>>>>>>` 成对出现（单个 `=======` 是合法 Markdown setext 分隔线）。
- `task-lifecycle-scan.py`：删除手写 `yaml.safe_load` 与 fallback 行解析，改调 `parse_issue_text`；解析失败写入既有 `metadata_validation_error` 字段（B1 与 B2 两处读取路径都覆盖）。
- `bin/issue-sync`：`_fm_get` / `_fm_set` / `_fm_has_key` 改为薄封装调用 `frontmatter_contract_cli.py`，33 处调用点不变。
- 新增 `lifecycle/frontmatter_contract_cli.py`：`get` / `has-key` / `set` / `check` / `repair`；`set` 优先 `write_issue()`（原子写），历史文档字段不全时回退同一模块原子写；`repair` 覆盖 B1 与 B2，默认 dry-run、`--apply` 幂等。
- 实际修复 23 份存量坏文档：12 份 B1（11 个 glued `---` + 1 个 git 冲突标记）+ 11 份 B2（6 个 YAML 内混入 bullet 行 + 5 个相邻字段粘连）。全量 B1 严格解析失败数 0。
- 五个测试夹具补齐对单所有者 CLI 的依赖（`test-platform-write-channel`、`test-issue-sync-close-terminal-first`、`test-issue-sync-promote-b2`、`test-feedback-severity.py`、`test-command-lifecycle-raw-metadata.py`），避免「夹具缺依赖 → `_fm_*` 静默失效 → 断言因错误原因失败」。

## 不退化边界

- `read_issue` 的正常路径逐字不变（只包装异常类型）；`issue-sync` 调用面与命令语义不变。
- 修复只改 frontmatter 结构与格式，不改任何元数据语义，也不改正文（副本一致性 body 投影不受影响）。
- 未删任何门禁检查；只是把「静默空 metadata」变成显式 `metadata_validation_error`。
- **历史格式保留**：无 YAML 块的 linked 文档仍按 `- key: value` bullet 解析（184 份、186 处 `phase_state` 不丢）；YAML 有效时不补 bullet，精确复刻收口前语义。
