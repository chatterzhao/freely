# Design Brainstorm: I-20261103T132517Z-A

## 决策 1：所有权收到契约模块，而不是新建第四套

`raw_metadata_contract.py` 已经是被 59 份 strict 文档、contract 测试与 `new_raw_metadata()` 自校验验证过的规范实现。新写一个「统一解析器」只会变成第四个所有者。因此收口动作是**删**掉另外两套，让它成为唯一入口；新增能力只加在它上面。

## 决策 2：解析失败必须有载体，不能返回 `{}`

`except Exception: pass` 是这条债务的根。改成「返回带 `__metadata_validation_error__` 的字典」而不是抛异常，是为了让 `read_issues_dir` 的两条读取路径（B1 raw / B2 linked）共用已有的 `metadata_validation_error` 字段落地，而不必改动 scan 的返回结构。`scan` 对外仍然是「一个 item」，只是 item 上多了一句人能读的原因。

## 决策 3：严格解析与历史格式必须能共存

初版实现把 bullet fallback 一起删了，全量实测立刻暴露：**184 份历史 B2 linked 文档被误判为「没有 frontmatter」**，186 处 `phase_state` 解析丢失。这不是「修好了旧债」，而是把旧债变成了 184 条新告警——正好复刻了我们要消灭的「AI 反复做无用功」。

修正后的口径：
- 有 YAML 块 → 严格解析，失败即 `metadata_validation_error`；
- 无 YAML 块但有 `- key: value` bullet → 这是历史格式，按 bullet 视图解析，**不报错**；
- YAML 有效时，**不**用正文 bullet 补字段（精确复刻收口前语义，否则正文里的说明列表会泄漏成 metadata）。

## 决策 4：冲突标记要成对才算冲突

`=======` 单独出现是合法 Markdown setext 标题分隔线。要求 `<<<<<<<` 与 `>>>>>>>` 同时存在才判冲突，避免把正常文档批量打成损坏。

## 决策 5：repair 覆盖两种此前没被发现的历史损坏

除已有的 glued `---` 与冲突标记，全量扫描又暴露两类：
- **YAML 内混入 bullet 行**（`- phase_state: dropped` 紧挨 `kind: linked`）；
- **相邻字段粘连**（`.../issues/3390- pre_tests_path: docs/...`，换行丢失）。

两类都用「文本级最小改动 + 严格解析复验」修复，且用字段白名单（`_KNOWN_FIELDS`）限制匹配范围，避免误伤正文里长得像 `- key: value` 的散文。repair 幂等：第二次 dry-run 必须报 0。

## 决策 6：`issue-sync` 的薄封装是硬依赖，测试夹具要跟着变

`_fm_*` 从「内联 python」变成「调外部 CLI」后，四个把 `bin/issue-sync` 单文件复制进临时树的夹具全部静默失效——`platform_state` 不再写入、`promoted_children` 不再更新、`severity` 标签消失。失败模式是**静默**的（`2>/dev/null || true`），只有对比断言才发现。

处置：真实打包走 `docs/system/workspace/scripts/` 整目录，已覆盖；缺的只是夹具。本轮为 4 个夹具补齐依赖，并在 AT-001 里用静态断言（CLI 存在 + `_fm_get` 是薄封装）守住这个接线点。

## 退化审计

1. `git archive develop -- bin docs .githooks templates` 出基线快照 + 最终版 AT-001 → RED `7 ok / 14 failed`；
2. 工位同断言 → GREEN `21 ok / 0 failed`；
3. 18 项相关回归与基线逐一对比退出码；
4. 全量 1082 份 B1+B2 文档解析结果逐字段对比：25 份差异 = 23 修复 + 2 新增，零意外退化；
5. 真机 repair 幂等（第二次 dry-run damaged=0）。

## 被否决

- **只修数据不收口所有权**：修完仍会复发，Manager 还会继续做无用功。
- **给 scan 再写一套严格解析**：变成第四个所有者。
- **把 184 份历史文档全量改写成 YAML**：改动面远超本 issue，且会让 `docs/` 历史 diff 不可读。
- **解析失败直接抛异常中断 scan**：一条坏文档会让整个扫描挂掉，比静默更糟。
- **`=======` 单独出现即判冲突**：会误伤 Markdown setext 标题。
