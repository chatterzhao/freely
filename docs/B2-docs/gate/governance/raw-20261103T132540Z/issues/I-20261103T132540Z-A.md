## 实现

新增单一 verdict 真源 `review_verdict.py`（Python 解析）+ `review-verdict.sh`（bash wrapper，导出 `freely_parse_review_verdict` / `freely_review_verdict_check`）。三个消费者共用：

- 读侧 `pr-merge-guarded`：review 块从「find 到文件就打印 pass」改为「读本地文件或远程 `git show` 内容 → 共享判定 → 非 pass 打印判定与原文 verdict 行并 exit 1」；判定函数缺失时同样 exit 1（fail-closed）。
- 写侧 `bin/pr-review-guarded`：`_review_verdict` 默认值由 `pass` 改为 `needs_changes`；`--verdict` 只接受 `pass|fail|needs_changes`、缺 `--reason` exit 2、reason 写入 review 文档（`- verdict_override_reason:`）；manual 模式拒绝覆盖。
- 审计侧 `governance-merge-gate`：`phase == "completed"` 不再裸 `continue`，改为要求「与该 issue 绑定的 review 产物 + 至少一份声明 verdict=pass」，显式 `fail`/`needs_changes` 不可被 completed 翻盘；`verification_artifact_dir` 的历史记账豁免保留。

## 不退化边界

历史两种 verdict 写法（`- verdict: pass`、`- verdict: **pass**`）都解析成功，401 份真实 review 文档零不可判定；`--dry-run` 仍不要求 review 文件；`.githooks/`、`commit-msg.sh`、R8 fail-closed 语义、R9.5 receipt 审计均未改；本轮回归基线对比零新增失败。

## 验收

AT-001 基线快照 RED（静态 13 项 FAIL、behavior 中止）→ GREEN `SUMMARY: 13 ok, 0 failed`；真实语料普查 `401 review docs, 399 with verdict, 0 unparseable`；真实工位 `verdict: fail` 反向探针阻断后还原，完成真实受控合并。
