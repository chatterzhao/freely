# Design Brainstorm: I-20261103T132540Z-A

## 决策 1：解析逻辑只能有一份

写侧（`bin/pr-review-guarded`）、读侧（`pr-merge-guarded`）、审计侧（`governance-merge-gate`）都要判断「这条 review 是否 pass」。三处各写一份正则就是 #4150 的成因（写侧写 `pass`、读侧不看内容）。因此解析落地为 `review_verdict.py` 一个真源，bash 侧只做薄 wrapper；测试里另加断言「merge guard 不得出现第二份 verdict 正则」。

中文注释与文档不参与判断 —— 只认 `verdict:` 字段名与取值，字段名即写读契约（登记去向见 #4154）。

## 决策 2：兼容历史两种写法，否则第一轮就自锁

真实语料普查：401 份 `pr-review-*.md`，399 份含 `verdict:`，其中本会话 R1..R9.5 共 9 份是 `- verdict: **pass**` 粗体，绝大多数是 `- verdict: pass`，另有 3 份历史 `fail`。解析器因此必须：

- 接受列表项前缀（`-` / `*` / `+`）与裸 frontmatter 键；
- 剥离 `**`、反引号、引号，容忍大小写；
- 空格/连字符归一为下划线（`needs changes` → `needs_changes`）；
- 只认 `pass` / `fail` / `needs_changes`，其余（含首条声明非法）返回 `unknown`。

## 决策 3：`unknown` 不等于 `fail`，但调用方必须 fail-closed

解析器返回 `unknown` 有两种来源：文档没有 verdict 行、或声明值不在契约内。前者是「没写」，后者是「写错」，都不能放行；但审计侧还需要区分「这份产物根本没声明 verdict」（例如同目录的 `implementation-decision-note.md`）与「声明了非 pass」。因此：

- 合并决策 `freely_review_verdict_check`：非 pass 一律阻断（含 `unknown`）。
- 审计侧：只要有任一变体绑定到该 issue，就要求其中至少一份 `pass`；但只有显式 `fail`/`needs_changes` 才算「被推翻」，避免把同目录的说明文档当成反对票。

## 决策 4：默认值必须反转，覆盖必须可解释

`pr-review-guarded` 修改前 `_review_verdict="pass"` 是默认值：`freely-review` 超时、空输出、输出里没有 JSON，全部落 pass。反转为 `needs_changes` 后，「判不出来」需要人来定夺，而不是自动放行。

`--verdict` 覆盖保留，但：

- 只接受 `pass|fail|needs_changes`，其他值 exit 2；
- 必须带 `--reason`，否则 exit 2；
- reason 写进 review 文档（`- verdict_override_reason:`），成为可审计痕迹；
- manual 模式下直接拒绝覆盖 —— 此时根本没有独立 reviewer，覆盖等于自签，正是 issue 里点名的滥用路径。

## 决策 5：`completed` 豁免只保留「记账」部分

修改前 `if phase == "completed": continue` 把 `verification_artifact_dir` 与 owner review 要求一起跳过。若整段要求照搬到 completed，历史大量缺失 `verification_artifact_dir` 的 issue 会立刻阻断每一轮合并（R8 的 `check-file-size` 自锁教训）。

因此 completed 分支改成：**不要求 `verification_artifact_dir` 字段，但要求该 issue 有绑定 review 产物且声明 `verdict=pass`**；显式 `fail`/`needs_changes` 不能被 completed 翻盘。这与 issue 修复方案第 3 条「至少保留 review 产物存在 + verdict=pass」逐字对齐。

## 退化审计方法

1. `git archive develop -- docs bin` 出基线快照（不含任何本轮改动），把**最终版** AT-001 拷进去运行 → RED；
2. 同样断言在工位运行 → GREEN；
3. 相关回归在未修改 develop 基线上逐一记录退出码与输出，与本轮结果比对；
4. 真实工位做反向探针：把 review 文档改成 `verdict: fail`，验证 `pr-merge-guarded` 与 `governance-merge-gate` 都阻断，再还原。

## 被否决的替代方案

读侧内联正则（第二份副本）；只认一种写法（历史不兼容）；保留无 reason 覆盖（滥用路径）；completed 全量套用未完成分支要求（立即自锁）；在测试里直接断言源码字符串而不测决策函数（无法证明行为）；夹带 #4149 / #4151（超范围）。
