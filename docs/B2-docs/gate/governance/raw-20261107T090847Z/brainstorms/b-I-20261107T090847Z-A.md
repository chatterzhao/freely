# Design Brainstorm: I-20261107T090847Z-A

## 决策 1：两代都认，不改写入方

历史里 `merge-guarded*` 1312 次、`pr-merge-guarded*` 683 次。只认新值会让历史审计大面积误报；改 `pr-merge-guarded` 写入值会制造第三代不一致。allowlist 同时接受两代是唯一低风险解，break-glass 仍走独立 ledger。

## 决策 2：控制流修复不得删检查

提前退出有 4 类根因：`check_entry_naming` fail 后 `return 1`；三个 check 对缺失文件跑 `rg` 得到 rc=2 作为函数最后命令；空 `entries=()` 在 `set -u` 下 unbound variable；audit 调用自身非零。修复方式统一为「`fail()` 已记录错误 → 函数返回 0」与「显式守卫」，绝不 `|| true` 掉整个检查或删除检查项。

## 决策 3：探针用真实 2-parent merge

`audit_current_protected_branch_merge_receipt()` 只在受保护分支且 HEAD 有 2 parents 时生效。隔离仓库用 `git merge --no-commit --no-ff` + `git commit` 构造真实 merge commit，才能覆盖真实判定路径；只 mock 字符串会漏掉 `rev-list --parents` 分支。

## 决策 4：抽取函数探针包含后置 helper

helper 定义在 audit 函数之后（389/407/413 行），探针必须从 `protected_branch_merge_source_allowed()` 一直截到 backfills 定义，否则 `command not found` 会让 CASE A/B/C/D 全部误判（本轮 RED 曾因此返工）。

## 决策 5：预存红测试的输出变化如实记录

两个 receipt 测试基线输出为 0 行（静默提前退出）、新版输出 12 条诊断 + 汇总行；退出码两版均为 1。这是修复带来的可观测性提升，不是回归，已写入 GREEN 证据。

## 退化审计方法

`git show HEAD:governance-check` 还原真源到未修改 develop，跑同一套 AT-001（RED 3 失败）与 9 个相关回归；恢复新版后同参数复跑，比对退出码与输出。

## 被否决的替代方案

只认新值（历史不兼容）；改写入值（新不一致）；删检查或整体 `|| true` 掉检查链（削弱治理）；把 audit 包进 subprocess 吞错误（掩盖而非修复）；夹带修 commit-msg.sh（R9 刚接线，越界）。
