# Design Brainstorm: I-20261107T120208Z-A

## 决策 1：不是「修 stop」，而是「把语义拆开」

#4135 报的是 stop 在 start 失败后仍写 `completed`。但源码显示 `start` 也写（`testing` + 新鲜时间戳），而门禁只排除 `not_tested` —— 也就是说**只要 start 过就能过门**。所以最小修法（只改 stop）不成立：`test-gate.env` 的语义被两种完全不同的东西共用（守护进程状态 vs 测试结果）。拆分后：守护进程状态归 `workcell-state.env`（已有 `write_workcell_state`），测试结果归 `test-gate.env` 且只由 `record` 写。

## 决策 2：`_test_gate_write` 单一写入点

字段集合（`TEST_STATUS` / `LAST_TESTED_AT` / `LAST_TESTED_COMMIT`）与原子替换只在一处实现。静态断言把「调用点数量 == 1」写进测试，避免以后又有人从别处 `cat >` 这个文件。

## 决策 3：拒绝要吵，不要静默

旧 `_update_test_gate` 对非 test 工位 `return 0`（静默跳过）。新命令对非 test 工位 `rc=2` 并说明「证据属于 test 工位」。理由：静默成功是 agent 手写状态文件的直接诱因 —— 它以为自己记录了，其实什么都没写。

## 决策 4：`completed` 必须带 commit，且必须可校验

`LAST_TESTED_COMMIT` 是门禁判断「是否在当前 HEAD 跑过」的唯一依据。默认取该工位 HEAD；若显式 `--commit`，先 `git rev-parse --verify <sha>^{commit}` 校验存在于该仓库，否则 rc=2 且不改文件。不校验就等于允许写入一个无法解释的哈希。

## 决策 5：不改门禁判定

`pretests-retirement-gate` 只排除 `not_tested`（`failed`/`testing` 都会通过）。收紧为 `== completed` 会影响历史工位与 #4151 的证据链改造，超出本条 —— 已写入 IDN 残余风险，并在 #4151 处理时一并评估。

## 决策 6：`wt-create` 初始化写入保留

初始化标记（`not_tested` + epoch 时间）不是测试结果，是「这个工位已初始化完成」的标记，语义不同、生命周期不同，保留原地写入，并在注释里指明两个写入者各自的语义边界。

## 退化审计方法

1. `git archive develop -- bin docs` 出基线快照，放入最终版 AT-001 → RED（14 失败）；
2. 工位同断言 → GREEN（20 ok）；
3. 7 个相关回归（wt-create ×3、write-channel、raw-metadata、wt-close、reconciliation）与基线逐一对比退出码；
4. 真实自举：用本命令给**本轮自己的** test 工位记录测试结果，再走 `pr-create-guarded`（命令解决自己的门禁）。

## 被否决

只改 stop；让 agent 走 daemon；把 test-gate 并入 worker-verification-contract；收紧门禁判定（#4151）。
