# Design Brainstorm: I-20261103T132509Z-A

## 决策 1：接线而非删除

README 已宣称三层、130 行实现完整；删除会削弱治理并需把文档降级为「仅事后审计」。接线复用 R8 完成的 `-f` fail-closed 模板，成本最低。

## 决策 2：shim 逐字节复用模板

模板用 `HOOK_NAME=$(basename "$0")` 拼 `${HOOK_NAME}.sh`，对 commit-msg 天然找到 `commit-msg.sh`，无需任何 hook 专属逻辑。用 `-f` 判定使 100644 真身不再被跳过。

## 决策 3：受控 handshake 是独立校验点

trailer 只是文本，自填合法值能通过字符串校验。探针实证 `git merge --continue` 会触发 commit-msg hook 且能看到 `FREELY_GUARDED_MERGE_COMPLETION=1` 与 `freely-guarded-merge-state`；手工 merge 两者皆无。因此校验 env + state 文件三字段 + source/target 与 trailer 一致，才能让「pr-merge-guarded 自复查」不再是唯一校验点。

## 决策 4：trailer 校验收窄到 develop/main

`is_protected_branch` 原含 `test-pre-merge-*`；每轮都要把 dev 提交 sync 进 test 沙箱（AGENTS.md 明确允许 merge/cherry-pick），要求 receipt 会自锁。隔离仓库 CASE D 验证收窄后通过。

## 决策 5：修复 pipefail 静默退出与 stdout 吞没

`grep|tail` 在 `set -euo pipefail` 下缺 trailer 会让命令替换失败、脚本在打印拒绝原因前退出；且 `cat <<MSG` 走 stdout 被 git 吞掉。改 `sed -n ...p`（总成功）+ 全部 `cat >&2 <<MSG`。CASE A 才从「静默 rc=1」变成「有明确原因的拒绝」。

## 决策 6：自举发现不夹带

`governance-check` 的 allowlist 与提前退出属独立缺陷（#4211 / R9.5）；本 PR 不改它，也不改 `pr-merge-guarded` 写入值。

## 退化审计方法

3 个真源用 `git show ba1a1ece8:<file>` 还原到未修改 develop（shim 删除即孤儿态），跑同一套 AT-001（RED 9 失败）与 13 个相关回归；恢复新版后同参数复跑。5 个预存红测试两版退出码与输出逐字节一致 → 0 新增失败。

## 被否决的替代方案

删除实现并把 README 降级（削弱治理）；保留 `test-pre-merge-*` 的 receipt 要求（自锁）；只校验 trailer 文本（挡不住自填）；改 pr-merge-guarded 写入值（制造新的不一致）；夹带修 governance-check（越界到 R9.5）。
