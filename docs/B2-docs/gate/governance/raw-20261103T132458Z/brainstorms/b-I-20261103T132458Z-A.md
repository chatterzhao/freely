# Design Brainstorm: I-20261103T132458Z-A

## 决策 1：shim 族精确定界，排除 post-checkout

6 个 shim 都以「真身存在则 exec」为契约；`post-checkout` 是自带完整逻辑的独立实现，且 `git worktree add` 必然触发它。无差别改整族会让每轮 `wt-create` 被自己的 hook 阻断。用 `git diff --quiet HEAD -- .githooks/post-checkout` 验证逐字节不变。

## 决策 2：`-f` 而非 `-x`

`exec bash <file>` 不需要执行位；`core.fileMode=false`、Windows 检出、zip 解包都可能丢失 `+x`。改用 `-f` 后，隔离仓库 CASE B 用 sentinel 证明「真身确实被执行」而不是静默放行。

## 决策 3：区分「freely 自举源码树」与「外部项目」

`pre-commit.sh` 的 `bin/worktree-common.sh` 缺失有两种语义：自举仓库里是环境损坏 → `exit 2`；外部项目里本就没有该 helper → 合法 `exit 0`。以 `./docs/system/workspace/hooks/pre-commit.sh` 是否存在作为判据，避免把「修复」变成「误伤全部外部项目」。

## 决策 4：file-size 门禁必须增量

全量 `check-file-size` 已有 7 个历史 `[ERROR]`（含 26,837 行 `runtime/freely`）。直接接入阻断 = 每轮 commit 必挂。新增 `--staged-only` early-exit 分支：只判断本次暂存文件；历史遗留仍可在全量运行中被看见。同时全量扫描扩展到无扩展名真源脚本，满足「`runtime/freely` 被点名报 ERROR」的验收。

## 决策 5：正常跳过与缺失跳过分开

`pr-create-guarded` 的「no raw key found in branch」是无 raw key 的合法路径；只有 4 处「门禁文件 not found」才是环境故障。静态测试同时断言两者。

## 决策 6：不动 `.githooks/bin/git` 的 PATH 接线

全仓无安装器/PATH 引用；接线会影响所有 git 调用，属独立基础设施改动。本 PR 保持 wrapper 原样，并在文档中如实标注残余风险，不宣称「无法绕过」。

## 决策 7：真实 commit 冒烟为强制验收

改的是每轮必经链路，隔离仓库测试不足以证明不自锁。在真实 R8 dev 工位执行一次 `git commit`（exit 0 / 1s），完整走过 shim → 真身 → file-size 增量门禁链。

## 退化审计方法

10 个真源用 `git show 94587c5f3:<file>` 还原到未修改 develop，跑同一套 AT-001（RED 26 失败）与 14 个相关回归；恢复新版后同参数复跑，比对退出码与输出。4 个预存红测试两版退出码与输出逐字节一致 → 0 新增失败。

## 被否决的替代方案

无差别改整族 shim（自锁 wt-create）；把外部项目也判为环境故障（误伤）；把 file-size 全量结果直接阻断 commit（自锁每轮提交）；把「no raw key」也改成失败（破坏合法路径）；给 `.githooks/bin` 注入 PATH（越界且高风险）。
