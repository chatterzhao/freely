# Design Brainstorm: I-20261106T100938Z-A

## 决策 1：显式补 5 行，不动白名单机制

`package-allowlist.txt` 的存在是 #4157「按目录 cp -R 会带出 __pycache__/ 与死代码」之后的收敛成果。改成自动包含整个 `docs/system/workspace/` 会把构建期文档、测试契约资料、遗留资料一并装进安装态，方向错误。因此只新增 5 行精确文件路径，并在注释里写明「不可改成自动包含」。

## 决策 2：3 个纯文档不随包，且 checker 扫描范围要排除 tests

`commands.md`（35 处 B1/B2 引用）、`three-loop-lifecycle.svg`（6 处治理文档）、`command-wrapper-metadata-lifecycle.md`（仅 1 处 `scripts/tests/test-command-wrapper-metadata-contract.py`）都不是运行时消费者。若 checker 把 `scripts/tests/` 也算运行时，就会把测试契约文档误判为「必需但未声明」，反过来逼迫打包它——这是典型的误改功能逻辑。因此 RUNTIME_DIRS 明确只含 `bin/` 与 `scripts/runtime|quality|worktree/`。

## 决策 3：与 R5 的 checker 正交，不重复实现

R5 `package-seed-parity.py` 管「gitignored allowlist 条目 ↔ seed manifest 声明」；本轮 checker 管「运行时引用的 tracked 顶层文件 ↔ allowlist」。两者输入、判定、失败文案都不同，合并会让职责模糊。改 `freely-package` 时严格保持 R5 hook 在前、新 hook 在后、两者都在 `rm -rf` 之前，输出守卫仍在最前。

## 决策 4：checker 只读、无 git 时降级、脚本缺失时跳过

只读（无任何写操作）；安装态没有 `.git`，`git ls-files` 不可用时降级为「枚举物理存在的顶层文件」，仍能检测；`freely-package` 在 checker 脚本缺失时跳过以兼容旧安装态（主仓库打包仍由 allowlist 复制循环 fail-closed，且既有后置 `integrity: verified` 校验兜底）。这不是 fail-open：被检查的「缺文件」本身仍会被复制循环拒绝。

## 决策 5：不改写既有后置完整性校验

`bin/freely-package` 尾部已有逐行断言产物存在的 `integrity: verified`。本轮补的是「声明完整性」而非「产物存在性」，因此不重复加后置循环，只加前置的声明一致性检查。

## 决策 6：诚实修正 issue 正文的一处表述

逐行核对后发现 `install-lifecycle-allowlist.txt` / `release-build-allowlist.txt` 是 repo-scoped（基于 `$project` 解析，且 `ensure_install_lifecycle_allowlist_file()` 会自动生成），不是安装态自身的清单；issue 正文「安装态 doctor 门禁缺清单」不准确。它们仍随包（tracked 运行时能力清单、保持产物等价、满足验收标准），但真正导致自举失败的是 `package-allowlist.txt`、`worktree-seed.toml`、`AGENTS.md.example` 三个 SELF_ROOT 真源文件。B1 brainstorms 与 IDN 均如实记录。

## 退化审计方法

用 `git show HEAD:<file>` 还原 2 个改动文件到未修改 develop 状态，同时临时移除新 checker，对 9 个相关回归同参数复跑，比对退出码与输出。结果 9/9 退出码相同（全 0），输出差异仅 `rm -rf` 行号 112→126（新增 14 行 hook）、随机临时目录名与计时数字，0 实质差异。

## 被否决的替代方案

自动包含整个目录（破坏 #4157 收敛）；把 3 个纯文档也打包（扩大安装态体积且无运行时消费者）；把防复发检查合并进 R5 seed parity（职责混淆）；批量改写历史安装版本（高风险无收益）；改 `worktree_seed.load()` 删掉 builtin 回退（破坏极简 checkout 兼容）。
