## 决策说明（Decision Note）

- decision: 复用 `wt-close --force --discard-unmerged` 骨架，在 `--force` 分支内部编排 `transition("dropped")` + 平台 `close_dropped`；adapter 新增 `close_dropped`（先写关闭评论再 `not planned` 关单，评论失败不关任何平台），并给 `pull_raw_issue` 加全 CLOSED 副本 fail-closed。**不新造 flag、不走正常 close 分支、不要求先手动 `issue-sync drop`**。
- why_this: `--force` 骨架本就跳过 dirty/phase/platform_state 三道门禁并完成关平台 + 删工位/分支，是 dropped 收口的天然落点；只缺「把关闭理由落盘到平台」这一环。就地接线代价最小、与既有收口路径一致，且不引入第二真相源（平台 `phase/*` 标签是创建时快照，不能写）。
- alternatives_considered: ① 新造 `--drop` flag + 走正常 close 分支 —— 与 FORCE 骨架重复且逼用户先 commit，反设计，已否决；② 给平台写 `phase/dropped` 标签 —— 第二真相源（L0 Q4），已否决；③ 要求先手动 `issue-sync drop` 再 wt-close —— 增加用户必须执行的 CLI 步骤，dropped 逻辑应内聚于 wt-close 编排，已否决；④ 不 commit 研究 + 新约束 —— 过度设计，FORCE 跳过 dirty 检查，提交与否都能收口，已否决。
- boundary_non_goals: 不把 B1 研究合进 develop；不追溯重开历史 issue；不走 `freely comment`（#4654 独立）；不改 `runtime/freely` 行数预算、不改 `validate()`/GATE 1；不新增 dropped 平台标签。
- residual_risk: `wt-close --force` 的 `--reason` 仍须带「违规绕过门禁中，理由充分，是：」前缀（既有门禁未放宽）；dropped 仅适用于 `phase_state=proposed` 的 raw（absorbed 不在 dropped 路径）；`pull_raw_issue` 全 CLOSED fail-closed 后若要重开须先在平台改回 OPEN。
