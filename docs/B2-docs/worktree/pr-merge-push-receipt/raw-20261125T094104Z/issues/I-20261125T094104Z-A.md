# I-20261125T094104Z-A: pr-merge-guarded issue-sync 源分支 push 回执 fail-closed

## 背景
`pr-merge-guarded._sync_issues_changed_in_merge` 在合并前自动 commit issue-sync 变更（platform_ids 等），随后 push 源分支。当前实现用 `git push all <branch> 2>/dev/null || true` 吞掉失败，并无条件打印 `[MERGE-GUARD] issue-sync committed + pushed to <branch>`。

实证（#4699 合并现场）：合并后 `github/fix/*` 停 `2905bdf67`、`all/origin/fix/*` 在 `0b56bc5f5`，回执未报失败。remote 'all' 含 github+gitee 双 pushurl，顺序推送，任一失败被吞后无法区分部分/全部成功。

## 目标
1. 逐 configured platform（跳过 all）push 源分支，汇总每平台结果。
2. 任一平台失败 → 非零退出 + 列出失败 remote + 可执行重试命令，不打印无条件 "pushed"。
3. 成功回执区分各 remote 状态，与同文件 develop-push 段（:401-423）范式一致。

## 非目标
- 不改 develop-push 段；不改 pr-create/pr-review；不改 adapter；不改 wt-close 删分支逻辑。
- 保留自动 push 的必要性，不去掉该步骤。

## 验收
AT-001：行为断言——成功路径逐 remote 回执 ok；注入 push 失败（mock git）→ 非零 + failed_remotes + 无虚假 "pushed"；源码断言——无 `push all ... || true`、无紧跟 commit 的无条件 pushed 打印。
