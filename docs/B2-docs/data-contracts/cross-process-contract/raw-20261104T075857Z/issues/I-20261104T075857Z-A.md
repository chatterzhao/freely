## 根因

Bash 与 Python 之间没有机器可读的数据契约。三类失败以前长得一样：
`state_file.values()` 对缺失 key 返回空字符串（调用方分不清「没有」和「空」）、
非字符串值被 `str()` 强转、超时与普通失败共用退出码。于是每个调用点各写一套
错误处理，任一处漏判就是静默错误。

## 影响

- 缺字段被当成空值继续执行，错误延后到不可归因的位置。
- 类型错误被强转后一路下传，最终表现为业务逻辑错乱而非契约错误。
- 超时不可区分，调用方无法选择重试或降级。

## 修复方案

1. `contracts/cross-process/contract.yaml`（JSON 兼容 YAML 1.2 子集）：state 文件协议、
   错误信封、退出码 0–4、四个 kind、超时语义、4 条已登记边界、已知缺口。
2. `docs/system/workspace/scripts/quality/cross_process_boundary.py`：把声明变成可执行，
   缺字段 → 3/`missing_field`、类型错 → 3/`type_error`、超时 → **4**/`timeout`。
3. `bin/check-cross-process-contract`（0/1/2）：校验契约完整性、边界生产方文件存在、
   runner 退出码常量与契约一致。
4. 单页文档 `contracts/cross-process/README.md`；AT-001 进 `CORE`/`CI_CORE`；
   `epic-runtime` 注册 `cross-process-contract` story（其后 epic 整体 +18）。

## 验收标准

- RED：develop `c159e6cef` + 最终版 AT-001 → `0 ok / 17 failed`。
- GREEN：工位同一断言 → `17 ok / 0 failed`；lint `ok (4 boundaries)`；`test-all --ci` 18/0。
- GREEN：三条边界真机可执行（`sh printf` 造缺字段/错误类型，`sleep` 造超时）。
- 不退化：`state_file.py` 一行未改；gate 逻辑未改；`bin/freely` 未改；22 处夹具未动。

## 刻意不做（known_gaps）

22 处测试夹具的 `source *.env`、33 处 `|| echo` 的逐点复核、消费方逐点机检，
都写进契约的 `known_gaps`，另立轮次，不夹带进本 PR 假装完成。
