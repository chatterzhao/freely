## 根因

R28 建立了 `skill-map.yaml` 单一真源与 frontmatter 契约，但 37 个 skill 的首跳阅读量
没有下降；删并又缺索引兼容期，直接删会留下悬空引用并丢失知识。四个低引用 skill
（引用 3–4，全部为 README/矩阵/历史 B1）可安全归并到三个语义入口。

## 影响

- 历史引用若指向被删 skill，`bin/skill-route` 无法解析即误路由。
- 只删目录会让 mem9 边界、signal 意图、Codex MCP 配置、chat 路由四份知识永久丢失。
- `supersedes` 全空，删并后无法追溯谁合并了谁。

## 修复方案

1. 全仓引用普查（7567 文件）形成候选清单，按语义分 3 组。
2. `skill-map.yaml` 增 `aliases`（4 条）与 `merge_groups`（3 组），删除 4 个 skills 条目。
3. 三个保留入口以「## 合并自」章节承接原 SKILL.md 正文，frontmatter `supersedes` 回填。
4. 删除 4 个目录；README 索引移除 retired 行并新增「别名迁移」说明。
5. 新增 `bin/skill-route`（名字/alias/loop 解析，0/1/2）；`bin/check-skill-frontmatter`
   增 alias 校验（悬空、仍存活、supersedes 未回填均 fail-closed）。
6. AT-001 进 `CORE`/`CI_CORE`；`epic-skills` 注册 `skill-merge-compat` story（其后 epic 整体 +18）。

## 验收标准

- RED：develop `faab26c14` + 最终版 AT-001 → `2 ok / 15 failed`（2 项为空集合负向守卫）。
- GREEN：工位同一断言 → `17 ok / 0 failed`；`bin/check-skill-frontmatter` → `ok (33 skills, 12 loops)`。
- GREEN：R28 AT 回归 `21 ok / 0 failed`；`bin/test-all --ci` `16 ok / 0 failed`；epics-map 16/211 对齐。
- 不退化：核心高引用 skill 一个不删；workflow 全链路、TDD 三阶段、dispatcher 三条 claim 路径、`runtime/freely` 不变。
