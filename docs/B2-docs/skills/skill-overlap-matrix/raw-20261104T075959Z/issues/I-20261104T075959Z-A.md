## 根因

`docs/system/workspace/skills/` 下 37 个 skill 没有机器可读的路由真源：frontmatter 只有
`name` / `description`，agent 判定入口只能逐个读正文；三组被 issue 判为「重叠」的 skill
实际是同一链路的不同阶段/owner；`freely-doc-B2_IBM-execution/SKILL.md:393` 还把
`pretests-gate` 的枚举复制了一份，改真源时必然漂移。

## 影响

- 首跳路由 token 成本高、误路由概率上升。
- 规则在多个 SKILL.md 各写一遍，无机器检测。
- 删并型重构没有 `supersedes` 落点，容易直接删出悬空引用。

## 修复方案

1. 新增 `docs/system/workspace/skills/skill-map.yaml`（JSON 兼容 YAML 1.2 子集，stdlib
   `json.loads` 可读）：37 个 skill 的 loop/owner/inputs/outputs/triggers、3 组重叠判定
   （`decision`/`entrypoint`/`reason`）、12 个 loop 的唯一路由入口。
2. 37 个 SKILL.md frontmatter 补 `loop` / `owner` / `supersedes: []`。
3. 新增 `bin/check-skill-frontmatter`：0 通过 / 1 契约违规 / 2 真源缺失（fail-closed），
   校验枚举、逐条一致性、孤儿、重复枚举措辞。
4. 消除 `freely-doc-B2_IBM-execution/SKILL.md` 的「从 gate 源码提取」重复标题，改为指向
   `docs/system/workspace/scripts/quality/pretests-gate` 真源。
5. AT-001 接入 `bin/test-all` 的 `CORE` / `CI_CORE`；`docs/epics-map.svg` 的 `epic-skills`
   注册 `skill-overlap-matrix` story。

## 验收标准

- RED：develop `49958c1d9` + 最终版 AT-001 → `0 ok / 21 failed`。
- GREEN：工位同一断言 → `21 ok / 0 failed`；真实语料 lint `37 skills, 12 loops` rc=0。
- GREEN：`bin/test-all --ci` `15 ok / 0 failed`；`check-epics-map` 对齐。
- 不退化：不删任何 skill、不改 skill 正文语义、不改 `runtime/freely` 一行。

## 刻意不做（另立 raw）

「至少 2 组完成合并、总数 ≤25」经前置评审证伪（三组为分工而非重复），删并需先建索引
兼容期（`AGENTS.md` / workflow / hooks / skill 索引 / 路由测试 / 打包白名单），已用
`freely feedback` 新建 raw 并排入 goal 队列，不夹带进本 PR。
