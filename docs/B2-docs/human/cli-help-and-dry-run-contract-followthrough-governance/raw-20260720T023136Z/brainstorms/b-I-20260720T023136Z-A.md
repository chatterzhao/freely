# b-I-20260720T023136Z-A: chat help 错误信息 shell 引号嵌套修复

## Input
- candidate C-20260720T023136Z-A（promoted）
- 根因：`docs/system/workspace/scripts/runtime/freely` L6700 `log_error` 参数用双引号包裹但内部嵌套双引号，外层引号提前闭合，`<描述>`/`<详细描述>` 落入非引号区被 bash 当作输入重定向，渲染为 `line 6700: 描述: No such file or directory`。

- 命令：`bash -c 'log_error(){ echo "$*"; }; log_error "[chat]   freely feedback --title "fix|feat: <描述>" --kind fix --body "<详细描述>""'`
- RED 输出：`bash: 描述: No such file or directory` + EXIT=1

## 方案评估
### Option A: 整体单引号包裹（选定）
- `log_error '[chat]   freely feedback --title "fix|feat: <描述>" --kind fix --body "<详细描述>"'`
- 单引号内 `<`、`>`、`"` 全部字面量；已验证 EXIT=0 且完整文本可读。
- 最小改动：只改一个字符串字面量，与 log_error 常规用法一致。

### Option B: 转义尖括号
- 保留外层双引号，对 `<` `>` 加反斜杠。可行但可读性差，嵌套引号容易复发。

### Option C: printf '%s'
- 改 log_error 调用方式，超出最小修复面。

## Decision: Option A
- 单引号整体包裹是语义正确的最小修复，规避重定向解释且保留中文与内层双引号。
