## Root cause chain

Five linked failure modes cause ACP bridge restart storms:

1. **`acp-bridge.py:241` KeyError**: `msg.get('result','')[:100]` fails when ACP server returns
   non-string `result` field. F-string slice triggers `__getitem__(slice)` → KeyError.

2. **Reader thread crash doesn't stop bridge**: `_read_stdout` only catches `ValueError/OSError`.
   KeyError escapes, daemon thread dies, bridge process stays alive holding socket → zombie.

3. **No health check on bridge reuse**: `_ensure_acp_bridge_running` only checks `kill -0` and
   socket existence. Zombie bridge passes both → reused → all requests timeout.

4. **bypassPermissions not propagated on resume**: `session/set_mode` was only called after
   `session/new`, not `session/resume`. Resumed sessions get `default` permissions → Write
   tools wait for interactive approval → stuck pending (AskUserQuestion is disallowed).

5. **server_lock held during wait blocks permission forwarding**: `_send_request` held
   `server_lock` during the entire 900s wait. Permission responses from client couldn't be
   forwarded to server stdin because `handle_client` (same thread) tried to re-acquire the
   non-reentrant lock → deadlock.

## Fixes

### acp-bridge.py
- Line 24: `BRIDGE_TIMEOUT` and `ACP_IDLE_TIMEOUT` now configurable via `ACP_BRIDGE_SESSION_TIMEOUT` and `ACP_BRIDGE_IDLE_TIMEOUT` env vars (defaults 1800s / 300s)
- Line 60: added `last_activity_ts`, `activity_lock`, `stdin_write_lock` to `__init__`
- Lines 217-231: `_read_stdout` catches `Exception` → bridge exits on unexpected error
- Line 215: activity timestamp updated on every server message
- Line 251: `str()` wraps result value to prevent KeyError
- Lines 269-336: `_send_request` uses activity-based idle timeout for `session/prompt`; releases all locks before waiting so permission responses can be forwarded
- Lines 364-376: `session_resume()` now calls `session/set_mode` after resume
- Lines 431-442: `handle_client` uses `stdin_write_lock` instead of `server_lock` for forwarding
- Lines 473-479: `handle_client` calls `session/set_mode` after both `session/new` and `session/resume`

### freely (bash)
- Lines 11855-11879: `_acp_bridge_health_check` — sends initialize probe via Unix socket
- Lines 11893-11896: health check gates bridge reuse; failed check → fresh restart

### run-acp-prompt.py
- Line 116: socket timeout configurable via `ACP_PROMPT_SOCKET_TIMEOUT`
- Lines 387-396: defense-in-depth `session/set_mode` after session creation

## Verification

- daemon start → bridge health check → session/resume → set_mode applied → AI completes cycle in <20s
- Write tool calls execute successfully (previously hung pending for 904s)
- No restart storms observed after fix
- Self-healing: broken bridge detected and restarted at startup
