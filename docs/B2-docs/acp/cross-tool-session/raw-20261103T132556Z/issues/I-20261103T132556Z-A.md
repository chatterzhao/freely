## 实现

- `run-acp-prompt.py`：`ACPClient` 新增 `session_id` + `set_session_id()`（main 会话协商后绑定）+ `_inbound_session_mismatch()`（仅在 positively-mismatched `params.sessionId` 时为真）；`_handle_message` 对 `session/update`/`session/request_permission` 入站过滤；`_handle_permission_request` 再加一道 session 守卫。
- `acp-bridge.py`：`AcpBridge.client_sessions`（sock→set[sid]）+ `_register_client_session()`（`handle_client` 在 params.sessionId 与 session/new|fork|resume 结果处登记，断开时清理）；`_broadcast_notification` 定向投递到 owner，未知/缺失回退广播（fail-open，绝不丢消息）；`bypassPermissions` 裸默认改 `default`，`FREELY_ACP_BYPASS_PERMISSIONS=1` 显式 opt-in，`CLAUDE_CODE_PERMISSION_MODE` 保持权威。
- 新增 `test-acp-session-routing.py`（4 静态 + 15 行为，隔离 mock，无真实平台/SDK）。

## 不退化边界

- 客户端：own-session、无 sessionId、未知自身 session 的消息一律保留旧路径（U6 不丢消息）。
- bridge：未知 session、无 sessionId、空注册表一律回退全广播。
- 权限：`CLAUDE_CODE_PERMISSION_MODE` 显式配置时逐字节不变（生产由 settings.json 注入）；显式 opt-in 仍可开 bypass。
- 其余 bridge/client 逻辑（会话协商、prompt 分派、server 存活、stdout 解析、set_mode）未改。
