# B2 Brainstorm: Agent Lazy-Start + Idle-Sleep + Task Auto-Wake

- candidate: C-20260708T202424Z-A
- issue: I-20260708T202424Z-A

## Option A 实现分析

### 改动 1: acp-bridge.py — Idle Monitor Thread

**方案：** 在 `start_server()` 中启动 daemon thread `_idle_monitor_loop`，每 30s 检查 `last_activity_ts`。空闲超过 `ACP_IDLE_TIMEOUT + 30s grace` → 记录明确日志 → 设置 `self.running = False` → `stop_server()`。

**关键代码：**
```python
def _idle_monitor_loop(self):
    while self.running:
        time.sleep(30)
        with self.activity_lock:
            idle_secs = time.time() - self.last_activity_ts
        if idle_secs > ACP_IDLE_TIMEOUT + 30:
            self.log(
                f"idle {idle_secs:.0f}s (limit={ACP_IDLE_TIMEOUT}s) — "
                f"no task for base_tool={self.base_tool or '(default)'}, "
                f"shutting down, restart on next task"
            )
            self._idle_timeout_detected = True
            self.running = False
            break
```

**边界考虑：**
- `last_activity_ts` 已有 activity_lock 保护，线程安全
- `_idle_timeout_detected` 标记让 `_send_request` 在 idle timeout 时设置 `stopReason=idle_timeout`
- `stop_server()` 清理 pid file、socket、进程树 → 干净退出
- 不改变 `_send_request` 中已有的 activity-based timeout（那是 per-prompt 的超时）

### 改动 2: freely — Daemon Startup Lazy-Start

**方案：** daemon 启动时只启动 manager_01 的 base_tool bridge。其他 base_tool 延迟到首次委派。

**关键代码（line 22281-22291 替换）：**
```bash
for _bt in "${_unique_tools[@]}"; do
  if ! _tool_is_registered "$_bt" 2>/dev/null; then
    log_error "..."
    exit 1
  fi
  _manager_slot=$("$_aq" --get-slot "manager_01" 2>/dev/null || true)
  _manager_bt="${_manager_slot%%-*}"
  if [[ "$_bt" == "$_manager_bt" ]]; then
    _ensure_acp_bridge_running "$project" "$_bt" || {
      log_error "failed to start ACP bridge for base_tool=$_bt"
      exit 1
    }
  else
    log_info "deferring bridge start for base_tool=$_bt (lazy-start, will start on first delegation)"
  fi
done
```

**边界考虑：**
- cycle 检查 (line 22388-22408) 保持不变 — 只维护已启动的 bridge
- 如果 manager_01 slot 不在 _unique_tools 中（比如 agent-table 只有 worker 没有 manager），fallback 到第一个 tool
- 不影响 `_ensure_acp_bridge_running` 已有的重启逻辑（检测 tool change 等）

## 替代方案评估

### 替代方案 1: 全懒启动（包含 Manager）
评估：Manager 总在巡逻，延迟启动增加首次 cycle ~5s 延迟，无实质性收益。不采纳。

### 替代方案 2: Bridge Sleep 模式（保留进程）
评估：Python 进程长期驻留 ~50MB 内存，且子进程管理增加复杂性。退出+重启更干净。

## 风险分析

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| Bridge 启动竞态 | 低 | Worker bridge 未就绪时委派失败 | `_ensure_acp_bridge_running` 已有 wait-for-socket 循环 |
| agent_next_free RPC 超时 | 低 | DB daemon 不响应 | fallback 到原 `grep agent-id.env` 逻辑 |
| Idle monitor false positive | 低 | Bridge 在有任务时误退出 | activity_lock 保护，仅在非 prompt 期间触发 |
| Manager bridge 是其他 tool | 低 | manager_01 slot 不是 daemon 当前 tool | 已有 tool-switch 检测逻辑，自动重启 |
