## 需要记录的两点

1. **`_home` 的引入是对“工位应当自包含”的一次让步**：工位只有 config.toml，项目级配置在 FREELY_HOME。本轮同时用“wt-create 复制 agent-table 到 test 工位”兜住 slot 解析，于是存在两条路径（复制 + 回落）。二者不冲突，但确实增加了理解成本；若后续统一，应保留回落、去掉复制。
2. **认领是写操作，发生在启动路径上**。失败时它只返回原因、不写库、不降级，行为等同修复前；成功时留一条 `owner-lane claim` 日志。可审计，但目前没有回收机制（行会留到 wt-close）。

## 残余风险（接受）

1. worker 工位的行若被误删（DB 损坏），该工位 daemon 会以 manager 身份启动。守卫收窄到“零行 + 唯一 manager + 真实 worktree + 分支可解析”，并有日志；根治要靠 C-B 的一致性巡检。
2. `wt-create` 复制 agent-table.toml 是拷贝而非链接：root 改 slot 后，已存在的工位不会自动跟随（与 freely.db 的复制策略一致）。
3. `rows_unreadable` 分支只有代码审查，没有独立用例（构造无 socket 的 DB 需要额外脚手架）。
4. owner 自审，无第三方独立性。
