# Design Brainstorm: I-20261105T062203Z-A

## 决策 1：复用 R3 的 `_wt_registered_dir()`，不新增路径推导

R3 为解决「分支在但工位目录不在」已建立 `git worktree list --porcelain` 反查真源。R4 是同一事实来源的第二个消费者，再写一套会引入双真源漂移。

## 决策 2：只改恢复块，不动另外 3 处

`freely_wt_resolve_target_path()` 的 hash 后缀是**新建工位的冲突避让**，在 `:948`（正常创建 dev）、`:967`（正常创建 test）、`:1082`（legacy 补建）都是正确语义。只有恢复模式下 dev 工位已存在，该函数才必然产生不存在的后缀路径。因此改动面严格限定为恢复块 2 处。

## 决策 3：反查失败是硬错误，不是降级

issue 修复方向 2 明确要求「反查不到时报错，不要猜测路径」。若回退到 `freely_wt_target_path_for_branch` 或 `freely_wt_resolve_target_path`，就会把本 issue 的缺陷以另一种形式保留。因此失败即 `exit 1`，并额外校验反查结果与 pre-flight 的 `_dev_dir` 一致。

## 决策 4：不夹带 #4201

RED 期间再次看到顶层 `return 1` 的 bash 语法错误，但该缺陷已独立立项为 #4201 / `raw-20261106T084804Z`，本 PR 不修。

## 退化审计方法

7 个回归测试（R1 门禁批量化、R2 物化 H1、R3 四态、Q1 恢复 + legacy、Q2 身份、命令生命周期）全部 PASS；RED/GREEN 证据记录带 `-300efa56` 后缀的错误路径与修复后的真实路径。

## 被否决的替代方案

改 `freely_wt_resolve_target_path()` 使其「目录存在时直接返回」（会破坏新建避让语义，影响 3 个调用点）；全局替换所有调用点（越界）；反查失败回退到推算路径（保留缺陷）。
