# Design Brainstorm: I-20261106T084804Z-A

## 决策 1：只改 3 行，不改函数内部 return

`wt-create` 是被 `bin/wt-create` 以 `exec bash` 直接执行的入口脚本，顶层代码不在任何函数内。函数内部的 `return`（22 处）是合法且必要的组合语义（`if ! _seed_worktree; then return 1; fi` 之类），改成 `exit` 会破坏 helper 与恢复路径。用括号深度分析精确定位：顶层恰好 3 处。

## 决策 2：不抽 main()，不改 shim

若把主流程收进 `main()` 并用 `BASH_SOURCE` 守卫以支持被 source，是另一个架构改动，需独立 issue。本轮只修非法控制流，保持 `exec bash` 唯一入口。注意 #4153 恰恰是「库文件被 source 时应把顶层 exit 改成 return」，方向**相反**——不能照抄。

## 决策 3：清理与文案逐字保留

三条失败分支的清理动作（worktree remove / branch -D 带 `|| true`）和错误文案都是既有验收契约，测试逐条断言存在；本轮只替换控制流关键字。

## 决策 4：行为测试必须注入三条分支而非只做静态检查

静态计数能防回归，但证明不了「失败时输出什么」。复用既有隔离 git 仓库骨架，用可注入的 stub（pull identity mismatch、dev seed 强制失败、test init 强制失败）真实跑完三条分支，断言退出码、业务文案、无 bash 语法错误、dev 分支已清理。

## 决策 5：预存红测试如实归类

`test-wt-create-source-local` 与 `test-wt-create-syncs-tooling` 在 develop 基线同码失败（#4151 覆盖），以未修改 HEAD 做基线对比证明 0 新增失败，不重复立项、不夹带修复。

## 退化审计方法

`git show HEAD:wt-create` 还原基线后跑同一套 AT-001（RED 4 失败）与 10 个相关回归；恢复新版后同参数复跑，比对退出码与输出。结果：9 PASS / 2 预存 FAIL 在两版完全一致，输出差异仅时间戳。

## 被否决的替代方案

把函数内 return 一起改（破坏组合语义）；抽 main() 支持 source（越界）；改 shim（破坏唯一入口）；顺手修四态判定/预存红测试（越界）。
