## 方案评估

1. **状态检测位置**：必须早于 :272 才能跳过 replica 网络检查，但 `freely_wt_resolve_target_path` 来自 `bin/worktree-common.sh`（:269 source），因此检测点定在 :269 之后。
2. **恢复执行位置**：必须晚于 :690（`_create_worktree` 定义完成），且早于 :694（跳过平台 issue 校验）与 :696（跳过远程 fetch）。
3. **初始化函数签名**：`_init_test_worktree_state <target_path>`，只负责 test 工位；dev 工位的 seed 仍由标准模式 :751 单独执行，避免恢复路径误改 dev 工位内容。
4. **base 推导**：legacy 分支从 `test-pre-merge-<raw-key>-<slug>` 提取 raw key，再在 `git branch` 中定位含 `raw-<key>` 且前缀为 `fix/`、`feature/`、`hotfix/` 的分支；找不到即报错，禁止回退到 `develop`，否则 test 工位会基于错误基线。
5. **幂等判定**：两个分支都存在时直接 exit 0，不触碰任何文件，保证自动化轮次重复触发安全。
