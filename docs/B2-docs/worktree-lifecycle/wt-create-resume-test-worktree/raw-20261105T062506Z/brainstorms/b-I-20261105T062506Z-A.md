# Design Brainstorm: I-20261105T062506Z-A

## 决策 1：required=false，避免干净 clone 新增硬失败

`worktree_seed.apply()` 对 `required=true` 且源缺失会抛 `SeedError`，`wt-create` 随即失败。全新 clone 没有 gitignored 的 `.freely/` 目录，若新条目设为 true，等于让所有干净环境无法开工位。改为 false 后，缺源只记 `missing` 并继续，打包阶段由既有 allowlist 校验 fail-closed——失败点仍在正确的位置。

## 决策 2：copy 而非 link

bootstrap 是静态文档；link 会让打包产物携带指向主仓库的符号链接，工位也无法独立打包。copy 让每个工位拥有自己的副本。

## 决策 3：一致性检查只读、复用单一真源

只比对声明，不改写任何清单。manifest 解析直接调用项目自己的 `worktree_seed.load()`，避免第二套 TOML 解析器产生语义漂移；仅在 seeder 缺失的极简 checkout 下才回退到最小 `path =` 解析。

## 决策 4：检查位置在 rm -rf 之前，且脚本缺失时跳过

放在输出路径守卫之后、`rm -rf "$OUTPUT"` 之前，保证任何输出清理之前就能拦下漏配；同时保留 #4158 守卫顺序（测试有断言）。脚本缺失时跳过是为了兼容旧安装态的打包产物（其中没有新 checker），主仓库打包仍由 allowlist 校验 fail-closed；这是兼容性折中，不是 fail-open——被检查的「缺文件」本身仍会被 allowlist 循环拒绝。

## 决策 5：不批量改写历史工位

当前 R5 工位是修复前创建的残留，用封装 seeder（`worktree_seed.py apply`）现场补齐，不手工 cp，也不批量改写其余历史工位。修复保证的是「此后新建的工位」自动正确。

## 退化审计方法

7 个相关回归用 `git show HEAD:<file>` 还原基线后同参数复跑，退出码逐一相同（全 0）；额外用主仓库作为基线验证输出守卫测试 PASS，确认 R5 工位失败只是残留而非代码回归。

## 被否决的替代方案

把 bootstrap 变成 tracked 文件（改变 gitignore 策略，越界）；把检查放在打包后（失败太晚，无法防复发）；seed 设 required=true（干净 clone 退化）；批量改写历史工位（风险高、无收益）。
