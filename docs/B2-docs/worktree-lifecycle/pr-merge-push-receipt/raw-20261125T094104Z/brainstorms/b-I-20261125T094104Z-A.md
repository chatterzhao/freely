## Goal
让 issue-sync 自动 commit 后的源分支 push 结果可信：逐 remote 校验、失败可见、可操作重试，消除虚假成功回执。

## 研究结论
- 同文件 `:401-423` develop-push 段已是正确范式：遍历 `git remote`（跳过 all）、逐 remote push、汇总 failed_remotes、全成功才打印 synced。
- `:623-629` issue-sync 段用 `push all || true` + `2>/dev/null` + 无条件回执，是三重缺陷。
- remote 'all' 有 github+gitee 双 pushurl，`push all` 顺序推送，任一失败被吞 → 无法区分部分/全部成功。
- #4699 合并现场实证：`github/fix/*` 停旧 commit、`all/origin` 新 commit，回执无失败。

## 方案评估
| 方案 | 结论 |
|---|---|
| 删 `|| true` 保留 push all | 否决——多 pushurl 无法定位失败平台 |
| 逐 remote push + 汇总（对齐 develop-push） | 采纳——同文件范式、改动最小、失败可见 |
| 抽公共 helper 两段复用 | 部分采纳——本轮先内联，避免触碰已稳定的 develop-push 段 |
| 失败即回滚 commit | 否决——过度设计，commit 正确只需可见性 |

## 测试设计
1. AT-001 源码断言：无 `push all || true`、无紧跟 commit 的无条件 pushed 打印、逐 remote 遍历存在。
2. 行为断言：mock git push 单平台失败 → 非零 + failed_remotes + 重试命令；双平台成功 → 逐 remote ok。
3. 回归：pr-merge 既有 AT + test-all --ci。
