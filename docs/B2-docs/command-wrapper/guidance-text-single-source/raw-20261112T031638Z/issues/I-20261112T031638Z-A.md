## 根因

**先定性（已查提交历史，见 B1 §1.0）**：`freely-fix-execution` /
`freely-feature-execution` / `freely-feat-execution` 是**真实存在过、于 2026-06-29
正式退役**的 skill，不是从不存在的名字。权威替代关系：

- `2495ca2af`（2026-06-29）`fix(wt-create): --kind replaces --skill for branch
  prefix selection` —— `--kind` 成为必填的分支前缀选择器，`--skill` 降级为可选
  覆盖（默认 `freely-workflow-guarded-execution`），旧 fix/feature SKILL.md 改 `.bak`；
- `a4029fa15`（2026-06-29）删 `freely-fix-execution/SKILL.md`、新增
  `freely-workflow-guarded-execution/SKILL.md`；
- `0486eee90`（2026-06-25）`feat` → `feature` 改名，故 feat 是 feature 的旧名；
- develop 上这三个目录与 `.bak` 均已不存在，`skill-map.yaml` 也未给它们登记 alias。

**本轮方向 = 补齐当年漏改的文案，把残留指引从已退役旧入口指向现行唯一入口，
不是回退、不是恢复旧 skill。**

R33（#4179）的「零幽灵 skill 名」验收只覆盖 **AGENTS 生成器与模板**两类载体
（`test-projection-consistency.py:179-186` 的 c13 断言）。但残留引用在仓库里有
**四类载体**：生成器/模板、`bin/` 与 `scripts/` 的运行时错误文案、文档、测试断言。
后三类全部漏网，于是本轮 `wt-create` 仍当场打印：

```
[ERROR] issue-sync refuses to run on protected branch: develop
  Bug fix:   skill:freely-fix-execution
  Feature:   skill:freely-feature-execution
  2. wt-create --raw-key <key> --skill <freely-fix-execution|freely-feature-execution> --slug <slug>
```

**根因是扫描域定义太窄，不是替换不彻底。** 只逐处改字面量会再次漏网。

同时证伪 raw 的一处描述：`--skill` **并未废弃**（`wt-create:22` 与 `:109` 仍在，
`commands.md:75/87` 正确记录为可选覆盖参数）。真正必填的是 `--kind`
（`wt-create:203` `Missing required: --kind`）。这些提示把可选参数当主参数展示、
漏掉必填参数，照抄会直接失败。故修法是**补 `--kind`**，不是删 `--skill`。

## 修复方案

1. **活代码文案**（全部改为真实 skill `freely-workflow-guarded-execution`，
   wt-create 指引补 `--source platform --kind <fix|feature|hotfix>`）：
   - `bin/issue-sync:126,127,131`（protected guard）
   - `docs/system/workspace/scripts/quality/pretests-gate:570`（`red_green_not_green`）
   - `docs/system/workspace/scripts/worktree/wt-close:1155,1159,1163`（UNMERGED 警告）
   - `docs/system/workspace/scripts/runtime/freely:1110,10771,11361,11407,13430`（帮助/拒绝文案，5 处）
2. **模板与文档**：
   - `docs/system/workspace/hooks/reference-transaction.sh:118`：修掉两个完全相同的
     重复选项（机械替换产物），改为 `--kind <fix|feature|hotfix>`
   - `docs/system/workspace/AGENTS.md.example:146`、
     `docs/system/workspace/three-loop-capability-lifecycle.md:206,359`：补 `--kind`
   - `docs/system/workspace/scripts/worktree/pr-create-guarded:158` 注释：
     prefix 由 `--kind` 决定而非 `--skill`，去掉同名重复
3. **测试反向断言**：`test-wt-close-protected-branch-guard` Test 6 当前断言
   「guard 必须含幽灵名才 PASS」——把错误固化成了判据。改为反向：不得含幽灵名、
   必须含真实 skill 名。Test 5 的 guard 文案断言同步对齐 wt-close 实际文案。
4. **AT-001 扩扫描域**：新增 `test-guidance-text-single-source.py`，扫描
   `bin/` + `scripts/`（排除 tests 黑名单常量与 `.bak.py`）+ 指定文档，
   白名单逐条写明理由；并含真实触发 guard 的行为断言。
5. **Step 2.5**：因触及 `runtime/freely`，同轮新增
   `docs/system/workspace/scripts/tests/unit/t-guidance-01.sh` 函数级单测。
6. `bin/test-all` 的 `CORE`/`CI_CORE` 各 +1 行；epics 注册
   `command-wrapper/guidance-text-single-source` story。
