## 1. 实现路径选择（B2 层，聚焦「怎么落地」）

### 1.1 文案单源化的落地形态

B1 已决定「单源常量 + 全域扫描」。B2 需决定常量放在哪、各载体怎么引用。

**Option 1：新建一份 `guidance.sh` 共享文案库，各处 source 它**
- 优点：真正单源。
- 缺点：`bin/issue-sync` 是 dispatcher（161 行，`bin-projections.yaml` 已登记），
  `pretests-gate` 是 Python，`runtime/freely` 是 27k 行单体，`AGENTS.md.example`
  是 Markdown 模板——**四种语言/形态无法共享同一个 shell 常量**。强行做需要
  引入生成器，改动面远超本轮，且会新增一个投影种类（需进 projection.lock）。
- 否决。

**Option 2（采纳）：文案就地修正 + AT 把「正确文案」作为不变量守护**
- 各处直接写正确文案；AT-001 用断言钉住「真实 skill 名 + 必填 `--kind`」这两个
  不变量，并全域扫描幽灵名。
- 单源性由**断言**保证而非物理共享：任何载体写错都会判红。
- 优点：改动面最小、不新增投影种类、四种形态统一适用；符合 R33 已建立的
  「AT 守护不变量」范式。
- 代价：文案字面仍有重复，但重复的正确性由 CI 保证，可接受。

**Option 3：只加扫描断言，文案逐处手改但不钉 `--kind`**
- 否决：`--kind` 缺失是本轮实测出的真缺陷（照抄会失败），不钉住会再次退化。

### 1.3 `--kind` 断言的判定方式

不能简单 grep「含 --kind」——`runtime/freely:1110` 是 usage 行，需含
`--kind`；而 `commands.md:75` 已含。判定方式：**对每个已知的 wt-create 指引
位置，断言该行同时含 `--raw-key` 与 `--kind`**。位置清单由 AT 显式列出
（file:line 会漂移，故用「文件内所有含 `wt-create --raw-key` 的行」动态定位），
避免行号硬编码。

### 1.4 反向断言的改造（Test 6）

`test-wt-close-protected-branch-guard:82` 当前：
```bash
if grep -q "freely-fix-execution\|freely-feature-execution" "$GUARD_FILE"; then
```
两个问题：① 断言方向反了（要求幽灵名存在）；② BSD grep 不支持 `\|`，
实测在 macOS 上恒 NO MATCH（本轮已实测：BSD basic NO MATCH / `grep -E` MATCH）。
改为 `grep -qE` 且方向反转 + 新增「必须含真实 skill 名」断言。
Test 5 的 guard 文案也需对齐 wt-close 实际输出（当前断言的字符串在
wt-close 里不存在，本轮实测 Test 5 同样 FAIL）。

**注意**：该测试当前不在 `bin/test-all` 里（本轮实测 `NOT in test-all`），
所以它的 FAIL 不影响 CI。本轮把它修好并**加入 CI**，否则修了也没人守护。

### 1.5 C-B 的传参落地

`bin/raw-issue-pull:133` 改为：
```bash
if ! "$ROOT_DIR/bin/issue-sync" --project "$caller_root" create "$local_id" >&2; then
```
`caller_root` 推导：脚本开头已有 `ROOT_DIR`（脚本位置）与 cwd。
`wt-create` 已 `cd "$fix_target"`，故 `$(pwd)` 即 dev 工位根。
为稳健起见用 `git rev-parse --show-toplevel`（在 dev 工位里返回工位根），
回落到 `$(pwd)`。**不改 ROOT_DIR 本身**——它仍用于定位 `bin/issue-sync` 脚本。
