# Brainstorm: manager-owner-stance-and-source-patrol-governance

## 核心边界

这条 issue 不再讨论：

- `PROJECT_INTENT / CONSTITUTION / LAWS` 应不应该继续约束 Freely 自举开发
- manager patrol 是否已经具备 dual-entry / restart-point routing
- evidence sufficient 之后的 delegation threshold
- active lifecycle 与历史边界如何区分

这些都已由现有 lifecycle 定义或承接。

这条 issue 只讨论：

1. 开发治理输入与产品能力真源的边界不能混淆。
2. 产品能力真源里的 manager persona 需要被直接写清。
3. human interruption 在产品能力真源里需要被明确为 advisory signal。
4. standing-source patrol 需要把 interruption / milestone / progress / pre-brainstorm 一并纳入 source completeness contract。

## 收敛结论

1. `docs/PROJECT_INTENT.md` 可以表达产品方向，但不直接充当运行期 manager / worker contract。
2. 运行期角色真源应落在 `docs/system/workspace/agents/**` 与相关 `skills/**` / references。
3. 主管的默认姿态应是“项目主人做全局判断”，不是“接到插话就把问题转回插话者澄清”。
4. 插话默认只是 signal；是否打断、并行、排队、冻结，由主管判断。
5. source completeness 不是一次扫描，而是主管把不完整来源推进到明确 lifecycle state 的事务。
