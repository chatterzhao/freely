## Implementation Decision Note

- decision: APPROVED
- why_this: Phase 0-3 batch scan replaces O(n) `gh issue view N` with single `gh issue list --state all` call. The approach is minimally invasive — core lifecycle chain trace logic is preserved, only the data source changes from per-item API to pre-loaded dict. All pre-tests scenarios are covered.
- alternatives_considered:
  - "Incremental: keep single `gh issue view` but add caching layer — rejected because it still makes N API calls on first run"
  - "Hybrid: batch only OPEN issues, lazy-load CLOSED on demand — rejected because chain trace needs CLOSED status for completeness"
  - "Current approach: single `--state all` batch, build platform_all dict, zero additional API" (selected)
- boundary_non_goals:
  - "Not changing the chain trace output schema"
  - "Not adding new scan phases beyond Phase 0-3"
  - "Not modifying how other platform scanners (gitee) work"
- residual_risk: "If `gh issue list --limit 1000` is insufficient for repos with 1000+ open+closed issues, the scan will silently miss issues beyond the limit. Mitigation: current repo is far below this threshold."
