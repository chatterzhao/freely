# Implementation Decision: worktree path architecture fix
- issue_id: I-20260618T015503Z-A
- decision: Unify ROOT_DIR resolution to `git rev-parse --show-toplevel` across all commands; materialize raw issues into worktree's docs/issues/ instead of develop; delete _absorb_close_frontmatter from pr-merge-guarded since raw issues arrive via merge naturally
- why_this: Current dual-track ROOT_DIR causes systemic path errors. Method A (git rev-parse) correctly returns worktree path when run inside worktree. Method B (dirname $0/../../../../..) hardcodes develop. Raw issues living in develop forces post-merge amend hacks that silently fail and dirty develop. Moving raw issues to worktrees eliminates the amend hack entirely and makes each worktree a complete self-contained project root.
- alternatives_considered: Keep raw issues in develop but fix amend reliability — rejected, doesn't fix the root cause. Use config.toml to specify paths — rejected, adds configuration burden for users. Use symlinks — rejected, git doesn't handle them well.
- boundary_non_goals: Not restructuring .freely/ runtime directory layout. Not changing how milestones.md is managed. Not migrating existing develop raw issues to worktrees (backward compat). Not adding automated path validation tests (future enhancement).
- residual_risk: Existing worktrees created before this fix won't have docs/issues/ directories — wt-create handles this by creating the directory. Commands run from develop will still see develop's docs/issues/ (acceptable — develop is the integration point). Governance-merge-gate needs updating to check worktree paths in addition to develop paths.
