# b-I-20261102T130603Z-A: handler 探活缓存与执行守卫

## Input
- candidate C-20261102T130603Z-A（promoted）。根因：`_handler_for` 每次网络探活，失败返回 None；`guarded_pr_update` 执行阶段无 None 守卫。

## 实现分析
- 新增进程级成功缓存 `_HANDLER_PROBE_CACHE`，只在 detect 成功时写入；失败不缓存。
- `_probe_handler(platform)`：命中缓存直接返回；否则遍历注册表，用 `_retry_read(lambda: True if handler.detect() else None)` 做有界重试；成功才缓存。
- `_handler_for` 改为薄封装调用 `_probe_handler`；`_discover_one` 去掉重复的二次 retry（内层已重试）。
- 新增 `_ensure_handler(platform) -> (handler|None, error|None)`；`guarded_pr_update` 执行循环改用它，None 时写入平台级 error 并 `continue`，不再抛 AttributeError。

## 替代方案
- 不探活只看配置：会把不可用误判为可用，失败后移，否决。
- 调用方各自重试：18 处消费会漂移，否决。

## 边界
- 只改探活/执行守卫；不改平台 handler 实现与 gate 语义。

- AC2（首次失败二次成功仍返回 handler）→ AT-002
- AC3（不可用返回结构化 error 不抛异常）→ AT-003
- AC4（既有门禁不回归）→ AT-004（guarded PR 链路 receipts）
