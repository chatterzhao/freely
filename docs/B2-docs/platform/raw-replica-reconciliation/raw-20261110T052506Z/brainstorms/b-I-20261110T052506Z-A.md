## 实现分析
- `pr_lifecycle.py`：新增 `BRANCH_SYNC_RECOVERY` / `ENVIRONMENT_RECOVERY` 两常量与纯函数 `recovery_for_plan(plan)`；`plan_platform_updates()` 把 `observation["error"]` 截断后放进 `details[platform]`。
- `platform-adapter.py`：新增 `GIT_FETCH_TIMEOUT_SECS = 30`；`fetch_branch_head()` 内收敛出 `run_git()` helper，三处调用共用 timeout 并把 `TimeoutExpired` 转成 `RuntimeError(f"{platform}: ... timed out ... (remote=..., branch=...)")`；`guarded_pr_update()` 失败分支改用 `recovery_for_plan(plan)`。
- 既有 `test-command-lifecycle-pr-update.py` 的 mock 用 `**_kwargs` 吸收新增 timeout 参数，无需改夹具。

## 替代方案评估
| 方案 | 结论 |
|---|---|
| 在每个 git 调用点各写 timeout 字面量 | 否决：会产生第二份口径（#4154 同族） |
| 把 recovery 分类内联在 adapter | 否决：plan 语义所有者是 `pr_lifecycle`，内联会产生第二份判定 |
| 一个平台失败仍推另一个 | 否决：破坏双平台一致性（R14.5） |
| 遇到 error 自动重试 fetch | 否决：重试策略归调用方 |

## 不退化边界
- `classify_branch()` 五状态与 `SAFE/BLOCKED` 集合逐字不动。
- `aggregate_results()` 逐字不动。
- all-or-nothing：`blocked_by_aggregate` 保留，`actions=[]` 保留。
- 成功路径 `push_branch` / `ensure_pr` 逐字不动。
