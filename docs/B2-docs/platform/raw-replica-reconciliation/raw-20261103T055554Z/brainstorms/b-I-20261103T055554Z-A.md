# b-I-20261103T055554Z-A: raw replica 身份解析按标题前缀

## Input
- candidate C-20261103T055554Z-A（promoted）
- 根因：`platform-adapter.py` 的 `search_raw_issue` 分别以 `raw-{key} in:title` 与 `in:body` 搜索并合并结果；body 中的交叉引用（其它 issue 的证据路径）会污染身份集合。`_discover_one`/`_unique_raw_issue` 要求恰好 1 条匹配，多匹配即 `ambiguous`，reconcile gate block。

## 实现分析
- 身份规则需要收敛到 platform-adapter 解析层的一个纯函数，供 `_discover_one` 与 `_unique_raw_issue` 共用：
  - 先按标题前缀 `^\[RAW-{key}\]`（大小写不敏感）过滤；
  - 恰好 1 条 → 采用；
  - 多条 → `ambiguous`（fail-closed）；
  - 0 条 → 回退到旧语义（恰好 1 条可用，多条 ambiguous，0 条 not found）。
- 这样 body 引用只影响"候选集合"，不再决定身份。

## 替代方案
- 只搜 title：会破坏没有 `[RAW-key]` 前缀的历史 issue 的 body 兜底，否决。
- 在各调用方分别过滤：身份规则重复、容易再次漂移，否决。

## 边界
- 只改 platform-adapter 的身份解析与调用点；不改 reconcile/scan 的消费逻辑。
- 不改 raw issue 标题/正文格式，不回写历史 issue。

## 验收映射
- AC1（标题前缀唯一命中优先）→ AT-001
- AC2（真机 discover 不再 ambiguous）→ AT-002
- AC3（多真实身份仍 ambiguous / 兜底单条）→ AT-003
