# Implementation Decision Note
- issue_id: I-20261108T092758Z-A
- decision: 以 `platform-adapter.discover_raw_replicas` 的平台侧身份为事实源；新增纯模块 `replica_guard.py` 把 receipt 判为 present/absent/indeterminate；`issue-sync cmd_create` 仅在本地缺 id 时咨询（present 回填不建、absent 照旧建、indeterminate 失败关闭拒绝建）；`cmd_close` strict 前用同机制回填 partial platform_ids（仅终态）
- why_this: R14 现场因 R6 降级 pull 只记了 Gitee，重跑 raw-issue-pull 的 `issue-sync create` 按 stale platform_ids 重复建了 GitHub #4224（真实 #4152 早已存在），`_resolve_raw_identity` 报 ambiguous 使 reconciliation 硬 block，收口全断。本地 `platform_ids` 是缓存，「本地缺 id」≠「平台无副本」；同一根因还让 close 只关一个平台。每轮 wt-create 都可能因平台抖动触发，dogfooding 杠杆最高。
- alternatives_considered: ①收窄 `search_raw_issue` 的 `--state all`/分页/title-only——R1 已证伪，破坏 identity resolution，否决；②ambiguous 时自动删重复——不可逆且无法判定对错，否决；③只改 raw-issue-pull 让 partial 不调 create——只挡一条触发链，create 自身裸缺陷仍在，否决；④每次 create 无条件 discover——健康路径加往返，否决；⑤present 改走 update 做标题归一化——扩大改动面，标题达标已由 Q2/R2 保证，否决。
- boundary_non_goals: `platform-adapter.py` 搜索层、`_resolve_raw_identity`、`close_platforms` 四段式与 0/3/1 退出码（R12）、`bin/raw-issue-pull`、`docs/epics-map.svg`（复用既有 `platform/raw-replica-reconciliation` story）全部逐字未改；健康路径零 I/O、零改写；linked/I-* 的 create/close 不受影响。
- residual_risk: ①`raw-issue-pull` partial 时仍调 create，但 create 已幂等/失败关闭，顺带减噪留待 #4166 或 `issue-sync reconcile`；②真机「降级→恢复」端到端未跑（不制造真实抖动），按验收标准用隔离 mock 固定 receipt 矩阵 + 真机 read-only discover-raw 组合覆盖；③stub adapter close-multi 恒返回全 closed，真实 0/3/1 由未改的 adapter 负责（基线对比已验证）；④`discover-raw --state all` 对已关闭副本也返回 ok，present 回填真实 id、不会新建 open 副本，安全。
- verification: AT-001 develop 基线 `a24ad958a` RED `7 ok / 13 failed` → 工位 GREEN `28 ok / 0 failed`；真机 `discover-raw 20261103T132548Z` → `replica_guard github|gitee` = present 4151/IKSPQ6（url 齐全）、unknown receipt = indeterminate；6 个相关回归（platform-write-channel / close-terminal-first / promote-b2 / protected-branch-guard / raw-replica-degraded / command-lifecycle-wt-create）基线对比退出码与输出逐字节一致（仅计时数字差异），0 新增失败；check-epics-map 16 epics/206 stories aligned。
