# I-20261125T071429Z-A: I-* 终态判据改为平台取证，关闭通道按 local_id 对账

## 背景

`wt-close` 是工位不可逆删除前的最后一道门禁。它当前判定 I-* 是否「已关闭」的依据，是本地 frontmatter 的 `platform_state`；而这个字段由关闭通道（`issue-sync batch` → `close_linked` → `platform-adapter close-multi`）写入，写入范围只覆盖 `platform_ids` 映射内的副本。于是同一个自述字段既是「已关闭」的写入证据，又是「可删除」的放行证据，平台真实状态没有任何一方校验。

实证：平台当前有 17 个 OPEN `[I-*]`，仅对应 10 个 distinct local_id；`#4654` 收口时 `I-20261114T111702Z-A` 在平台上没有任何副本，本地却写着 `platform_state: closed`，`wt-close` 直接放行。

## 目标

1. 终态判定改为**平台取证**：任一 configured platform 上存在该 local_id 的 OPEN 副本 → 拒绝收口；平台不可读 → 也拒绝（fail-closed）。
2. 关闭通道**按 local_id 对账**：枚举所有真实副本（含未映射到 `platform_ids` 的孤儿与重复），全部关闭才写 `platform_state: closed`。
3. 失败**不再被吞**：`issue-sync batch` 汇总退出码；`pr-merge-guarded` 在 batch 非零时中止合并。
4. 消除**重复创建**：平台已有同名副本时不再 create。

## 非目标

- 硬拦截层（PATH wrapper 拦截 `gh issue close` / 内层 adapter 直写）不在本 issue：它是独立的执行环境机制，需单独 B1/B2。
- 不清理历史遗留的 17 个 OPEN 副本；本 issue 只保证「不再新增 + 不再放行」。历史清理走独立治理轮次。

## 验收

- AT-001 静态+行为双段：adapter 暴露只读枚举且过滤正确；`wt-close` 在 Phase 2.5 调用取证；`cmd-batch.sh` / `pr-merge-guarded` 不存在吞错写法。
- 误拒风险：取证只在 `phase_state in (completed, absorbed)` 的 child 上执行，且只匹配标题含 local_id 的 I-* 标题。
