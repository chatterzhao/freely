# Design Brainstorm: I-20261104T082542Z-A

## 决策 1：H1 文本由共享契约派生，不在 adapter 里另写剥离

`_local_record()` 把 H1 当本地 title；`canonical_projection()` 把平台 title 的 `[RAW-<key>] ` 前缀去掉。两者要相等，H1 必须是「canonical title 的 human 部分」。Q2 已有 `canonical_raw_title()` 作为平台标题唯一真源，因此新增 `local_heading_title()` 委托它，再剥掉自己刚构造的精确前缀。这样任何达标规则变化只改一处。

## 决策 2：精确前缀剥离，而不是复用 `_STALE_PREFIX`

`_STALE_PREFIX` 只匹配时间戳形状 key。4 个历史非标准 key（`20260501` / `20260503` / `20260503-0000` / `MIGRATED`）会让它剥不掉前缀，`canonical_raw_title()` 从而产出重复前缀。修改 Q2 既有正则会改变其行为（用户禁止退化），因此在新 helper 里先用 `^\[raw-<exact key>\]\s*` 剥前缀再委托，`_STALE_PREFIX` 仅作二次兜底。已对 4 个 key 加回归断言。

## 决策 3：幂等优先于「修正历史」

body 已有 `# ` 行时保留原样（含 18 份多 H1 的历史文件）。回填命令同样：已有 H1 一律逐字节不动。理由是这些文件可能已 absorbed、已被其他治理链引用，擅自改动会制造新的 diverged。

## 决策 4：回填命令默认 dry-run，且绝不瞎编标题

700 份缺 H1 的历史文件中仅 6 份有 `issue_title` frontmatter，690 份有平台 issue_id，410 份已 absorbed。因此：
- 无可靠标题来源 → SKIP 并列出，不猜、不用 `raw-<key>` 占位；
- 平台查询只在 `--no-platform` 未指定时进行，异常一律吞掉并 SKIP；
- `--apply` 必须显式、`os.replace` 原子写、写前二次检查 H1、可重复执行。
- 本 PR **不执行**批量回填：700 个文件的改写应独立评估，且多数已终态。

## 决策 5：H1 放在 frontmatter 之后、正文之前，且只占一行

`_local_record` 用 MULTILINE 正则取第一个 `# ` 并把它从 body 中剥离；`canonical_projection._body()` 对平台 body 做同样的 frontmatter 剥离与空白折叠。因此渲染格式 `---\n<fm>\n---\n\n# <heading>\n\n<body>` 能让两侧 body 与 title 同时对齐。折叠空白保证 H1 不跨行。

## 退化审计方法

1. 805 份真实 B1 issue.md，分别以 `git show HEAD:raw_title_contract.py` 与新版模块加载，对四个既有函数逐项比对输出 → 0 差异。
2. 真实双平台副本（#4181 / IKSWR8）实际 `pull_raw_issue()` 到临时目录，用 `canonical_projection` 计算本地/平台 fingerprint → 一致（`9140d678763e4dd9`）。
3. 7 个相关回归测试（含 Q1 / Q2 / R1 的测试）全 PASS。
4. 4 个非标准历史 key 的 H1 前缀无关性单测。

## 被否决的替代方案

- 在 `wt-create` 或 `issue-sync` 里现场补 H1（不是真源修复，每轮仍要人工）。
- 直接改 `canonical_raw_title()` 的 `_STALE_PREFIX` 以支持任意 key（改变 Q2 既有函数行为，越界）。
- 本 PR 批量回填 700 份历史文件（410 份已 absorbed、18 份多 H1、标题来源不足，风险不可控）。
