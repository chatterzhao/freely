# Design Brainstorm: I-20261105T122053Z-A

## 决策 1：复用 scan 既有 `__degraded__` 消费者，不改 scan 真源

`task-lifecycle-scan.py:773` 已经把 `__degraded__` 弹出并设置 `platform_health=degraded`；`get_platform_open_issues()` 直接返回 adapter 聚合结果。issue 修复方案第 3 条建议改 `get_platform_open_issues()`，但评审发现属多余：只要聚合层产出标记，既有降级语义立即生效。不改 scan 既减少改动面，又满足「调用方无需改动」。

## 决策 2：`__degraded__` 只在失败时出现

验收标准要求健康时返回 107 条且结构不变。若把结果改成 `{records: ..., health: ...}` 包裹结构，所有调用方都得改，且违反验收。因此采用「保留键」方案：健康时零额外键，失败时附加一个 `__degraded__` 键（scan 会 pop，不会污染下游 `_build_raw_key_index` / `get_all_platform_issue_states`）。

## 决策 3：handler 用实例状态而非改返回值签名

`list_open_issue_records()` 的返回契约是 `dict[str, dict]`，被 `list_open_issues()`、parity、聚合层共用。若改成返回 `(records, health)` 或包裹对象，会破坏多处调用。改为在 handler 上记录 `read_health`，聚合层读取该状态——健康路径返回值逐字节不变。

## 决策 4：REST 合法空响应 ≠ 读失败

根因的一半是把「REST 返回空」和「REST 调用失败」都压成 `{}`。修复后只有 `returncode != 0` / stdout 空 / 解析异常才 `ok=False`；合法 JSON（含 `[]`）表示读取成功，即该平台确实没有 open issue。这保留了「无 open issue」与「读失败」的语义区分，是修复的核心。

## 决策 5：聚合层显式 try/except，不再用 `_safe`

`_safe()` 把异常转成 `{"status": "error", ...}`，旧聚合层把它当记录 `**record` 展开（TypeError 或伪造 `github:status`）。修复后逐 handler 显式捕获、跳过非 dict 记录，异常也成为降级标记的一部分。

## 决策 6：parity 在降级时跳过而非「尽力比较」

部分清单算出的 `github-only`/`gitee-only` 是假差异，比不比较更危险（会诱导误清理）。因此 `collect_open_issues()` 返回 `(openings, degraded)`，main 在降级时打印 SKIP + 重试提示并 return 0。健康路径仍执行原有的逐 key 比较与本地文档校验。

## 退化审计方法

2 个真源用 `git show HEAD:<file>` 还原到未修改 develop，跑同一套 AT-001（RED 5 失败）与 12 个相关回归；恢复新版后同参数复跑。退出码逐一相同（全 0），输出差异仅计时数字。另用真实双平台读取验证健康路径 102 条无 `__degraded__`。

## 被否决的替代方案

改 scan 真源（多余，已有消费者）；把聚合结果改成包裹结构（破坏所有调用方与验收）；删除 REST 回退（丢失独立通道）；让聚合层抛异常（中断所有调用方）；把失败标记当普通 issue 记录（污染 issue 集合）；改 `pull_raw_issue()` 或写通道（越界到 R6 / R11）。
