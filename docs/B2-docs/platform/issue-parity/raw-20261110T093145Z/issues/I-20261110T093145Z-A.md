## 前置评审修正了立项假设

立项时以为「物化没写 H1」；实测发现 H1 注入逻辑早已存在（commit `e219b49b4` / #4181），项目还有 `raw_title_contract` 单一所有者、`test-materialize-h1` 护栏与 `bin/raw-issue-backfill-h1`。真正根因是**三处裸 `^#\s+` 正则都不排除 fenced code block**：#4264 的 body 含行首 `# -> StateFileError...` 的 python 注释（第 59/61 行），被当成已有 H1。

## 实现

- `sync/raw_title_contract.py` 新增 `find_local_heading(body)`：逐行扫描，跳过 ``` / ~~~ 围栏（0–3 空格缩进、长度 ≥3、闭合需同字符且长度 ≥ 开启），返回代码块外第一个 `^#[ \t]+\S` 的标题与结束偏移；无真实 H1 返回 `None`。返回偏移是为了让 gate 沿用原有的 body 切片语义。
- `sync/platform-adapter.py::pull_raw_issue` 改用它判定是否注入 H1 —— 含代码块注释的 body 现在会正确注入真实 H1。
- `lifecycle/raw-reconciliation-gate.py::_local_record` 改用它提取 LOCAL title；不再借代码注释、不再丢弃正文。main 在 `--require-local` 且无真实 H1 时追加显式诊断 `missing_local_title`（指向 `raw-issue-pull` 重新物化）。
- `bin/raw-issue-backfill-h1` 两处（扫描判定 + `--apply` 幂等复检）改用它；含代码块注释但缺 H1 的历史文档现在能被修复。
- 新增 `tests/test-raw-title-codeblock.py`（AT-001，14 项）。

## 不退化边界

- 既有契约函数 `canonical_raw_title` / `local_heading_title` / `is_canonical_raw_title` / `platform_title` 一字未改，Q2 兼容分支与身份回退保持。
- `tests/test-materialize-h1` 18 项全绿（单元 / 静态 / backfill 三组）。
- 不放宽副本一致性检查（仍 fail-closed），只是诊断从误导性的 `content_diverged` 变成可操作的 `missing_local_title`。
- 不改 `canonical_projection` 的 labels / comments / state / severity 比较维度。
- 未批量回填历史 B1 文档，未删除任何文件。
