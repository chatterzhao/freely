- title: issue-sync 拆子命令模块 + 平台投影单一契约

从 #4166（`raw-20261104T080014Z`）拆分。R26 已把平台写收口到
`platform-adapter.py`；本 issue 处理剩下三项。

## 根因

1. `bin/issue-sync` 是 1330 行单文件：`main()` 只占 64 行，其余全是函数，任何
   子命令都无法单独 source 或断言，改动只能端到端验证。
2. 平台 body 与标签有**两套实现**：`_labels()` 在 shell 里拼标签，`feedback`
   另有一份 `kind/raw,phase/proposed,severity/Pn` 字面量；`_issue_body()` 的
   `awk` 只删 `---` 行、不删 frontmatter 键，于是 YAML 键值被当正文发给平台，
   而 `feedback` 发的是带围栏的 frontmatter —— 同一份文档两条路径两种产物。
3. `bin/issue-sync-bootstrap --delete` 直连 `gh issue delete`，是 adapter 之外
   唯一的平台写入口，既没有 repo 解析也没有错误语义，且未登记例外。

## 影响

拆分前任何 issue-sync 改动都要跑全链路；body/标签的「基本一致」在第三个入口
出现时会再次分叉；平台删除的 repo 归属与失败语义依赖调用者当前目录。

## 修复方案

1. `bin/issue-sync` 只保留 `ROOT_DIR`/`ISSUES_DIR` 解析、模块加载、受保护分支
   守卫与 `main()` 分派；`_issue_sync_rebind_paths()` 让 `--project` 之后的
   派生路径（`SCAN_STATE` / adapter / guard / contract / `_FM_CLI`）跟随切换。
2. 新增 `bin/issue-sync.d/`：`lib-frontmatter.sh`、`lib-state.sh`、`lib-replica.sh`、
   `lib-content.sh`、`lib-platform.sh`，以及每子命令一个 `cmd-*.sh`（9 个）。
   加载器按固定顺序 source，缺任一模块即 fail-closed 并报出缺失文件名。
3. 新增 `docs/system/workspace/scripts/sync/issue_create_contract.py` 作为平台投影
   单所有者：`strip_frontmatter`、`split_workflow_kind`、`drop_comment_channel`、
   `platform_body`、`labels_for`，并提供 `body` / `labels` 两个 CLI。
   `lib-content.sh` 的 `_issue_body` / `_labels` 与 `freely feedback` 全部改调它。
   平台 body 保留**带围栏的 frontmatter**（`pull_raw_issue()` 依赖它选择严格
   materialize 分支），人类正文与 `### comment-` 通道分离。
4. `platform-adapter.py` 增加可选 `delete_issue()`（GitHub 实现）与
   `issue-write-one <platform> delete <number>` 分派；`bin/issue-sync-bootstrap`
   的 `--delete` 改为解析 issue 编号后调 adapter，repo 由 adapter 统一解析。

## 验收标准

- RED：`bin/issue-sync` 1330 行且无 `issue-sync.d`；无契约模块；`feedback` 含
  标签字面量；`bootstrap` 直连 `gh issue delete`；平台 body 无围栏、含 comment 正文。
- GREEN：主文件 ≤ 665 行（实测 161）且不含任何 `cmd_*` 定义；9 个 `cmd-*.sh`
  各自定义对应函数；source 主文件后 11 个入口全部可用；`_labels` 与契约对
  P0/legacy 文档一致；`_issue_body` 与契约输出逐字节相同、只含一处
  `schema_version`、保留 `workflow_kind`/表格/人类正文、丢弃 `## Comments`；
  `bootstrap --delete` 下 `gh` 收到 `issue delete 42 --repo acme/demo --yes` 且
  stdout 为 adapter 的 JSON 回执。
- 不退化：`issue-write-one` 契约、0/3/1 退出码、promote/close 行为、
  `raw_title_contract` 的标题投影不变；`test-all --ci` 12/0。
