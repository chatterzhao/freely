# B2 brainstorm: 交接运行时 P0 修复

## 1. 输入

- candidate：`C-20261101T140415Z-A`（promoted）。
- 验收：`_do_new` 三条路径首条消息送达；存活判定三态；不改 A2A/CLI/agent-table。
- 证据：`agent_working.py:223-232`、`watchdog_sse.py:120-140/450`、`a2a_server.py:598`。

## 2. 方案评估

### 方案 A：最小修复（选中）

- `_do_new` 增加 `message` 参数，两个调用点传入；模块顶部 `import sys`。
- `watchdog_sse` 新增 `_session_state()`：`session/ping` 返回 result → alive；返回 error → dead；bridge 不可达/异常 → unknown。
- `_check_agent_liveness` 只在 dead 时清绑定；unknown 只记日志。
- 新增 `test-handoff-runtime.py`，覆盖 `acp_session_connect` 的 `_do_new` 路径与 `_session_state` 三态。

优点：改动面 2 个文件 + 1 个测试；能直接消除“随机丢交接”的最大来源；为 C-B 的 outbox 留出接入点。
缺点：不解决根本的“无队列”，但那是 C-B。

### 方案 B：A + 持久 outbox

- 在 `a2a_tasks` 之外新增 `handoff_outbox`，`prompt` 先入队，watchdog 消费并回执。
- 需要新表、状态机、消费循环、迁移与回放测试。
- 结论：超出本 candidate；作为 C-B 的 B2 输入。

### 方案 C：重做 Ticket/Assignment

- 用 `delegation_tasks` 取代 `a2a_tasks` 语义，席位与 assignment 分离。
- 结论：与现有 A2A 兼容性冲突，迁移风险大，不做。

## 3. 关键设计决定

1. **首条消息只发一次**：`acp_session_connect` 的 `force_new`、`resume`、`fork`、`new` 四条路径统一调用 `_prompt_after_connect`，避免某条路径静默无消息。
2. **三态存活**：`session/ping` 的 `error` 才代表 dead；`None`（bridge 不可达）代表 unknown，不清绑定，避免网络抖动造成假 DEAD。
3. **不写消息历史**：首条消息仍只走 `session/prompt`，不写 `messages_json`；写历史属于 C-B 的信封设计。

## 4. 风险

- `session/ping` 在旧 bridge 上可能不支持 → 返回 error → 被判 dead。为降低风险，仅在错误文本包含 `session`（如 `session not found`）时判 dead，其余错误判 unknown。测试覆盖该分支。
- `_do_new` 增加参数后，所有调用点必须同步；用 `grep` 与测试双重确认。
