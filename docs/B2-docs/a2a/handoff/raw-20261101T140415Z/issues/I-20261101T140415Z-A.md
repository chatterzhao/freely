# I-20261101T140415Z-A: 交接运行时 P0 修复

## 背景

`a2a-exit` 的交接链路有两处可复现缺陷：

1. `agent_working._do_new` 的函数签名没有 `message`，函数体却调用 `_prompt_after_connect(..., message)`；`sys` 也未在模块级导入。跨工具交接、`session/resume` 失败回退、无 manager 会话三条路径都会抛 `NameError`。
2. `watchdog_sse._handle_sse_event` 不捕获该异常，`watchdog_run` 记 `SSE error` 后重连；`/tasks/stream` 是内存 `asyncio.Queue`，断线不重放，交接静默丢失。
3. 上游 `_check_agent_liveness` 用 `pgrep -f <session_id>` 判活，误标 DEAD 后清空 session 绑定，把下一次交接推入第 1 条路径。

## 根因

- 首条消息只在 `acp_session_connect` 的 `force_new` 分支被发送；`_do_new` 是后来抽出的公共函数，抽离时漏传 `message`。
- 既有测试 `test-acp-handoff.py` 只直接调用 `_prompt_after_connect`，没有覆盖 `_do_new`，所以缺陷一直 GREEN。
- 存活判定用进程名匹配，而 `run-acp-prompt.py` 的命令行不含 session_id；ACP bridge 已有 `session/ping` 却没有被使用。

## 目标

- `_do_new` 三条路径都能在新会话建立后送达首条 handoff 消息，并带 `[role:<role>]`。
- 存活判定改为 `session/ping` 三态（alive / dead / unknown）；unknown 不清绑定。
- 回归测试覆盖上述两条，且不改变 A2A 状态、CLI 参数与 `agent-table` 语义。

## 非目标

- 不实现持久 outbox / 交接信封 / owner 绑定（属于 `C-20261101T140415Z-B`）。
- 不重命名 `worker_NN`，不改 `agent-table.toml`。
- 不改 `watchdog_sse` 的 SSE 传输形态（仍是内存流）。

## 验收

见 `verification/pre-tests.md` 的 AT-001 / AT-002 / AT-003。
