# B2 Brainstorm: A2A→SSE→ACP 消息投递链 + SQLite 友好校验

## 候选方案评估

### 方案 1: 完整链路 + SQLite 校验层（采用）

**消息投递链**:
```
Agent A → a2a_task.py prompt → POST /tasks/{id}/messages
  → SQLite Gate 1-3 (content非空 / role合法 / task存在)
  → SSE message_added → watchdog_sse
  → agent_working lookup → ACP session/prompt → Agent B
```

**SQLite 三层校验 Gate**:
1. content 非空 — 空消息无意义
2. role ∈ {manager, worker, reviewer} — 合法角色枚举
3. task 存在 — 避免写入不存在的任务

每层失败返回 `{valid: false, error, fix_hint, example}` — 用中文告诉 AI 哪里错了、怎么改、正确格式是什么。

**4 文件改动**:
- `a2a_server.py`: message_added SSE + 422 错误响应
- `freely_db_manager.py`: 3 层 SQLite 校验 gate
- `watchdog_sse.py`: `_handle_message_delivery()` ACP 投递
- `a2a_task.py`: stderr 友好错误输出

### 方案 2: 仅投递链，不加校验
只打通 SSE → watchdog → ACP，不加 SQLite 校验。

不采用原因: AI 写错格式时仍然静默失败，不知道错在哪、怎么改。

## 实现方案

### 1. freely_db_manager.py — 校验层核心

3 个 gate，每个返回结构化错误:

```python
# Gate 1: content 不能为空
if not content.strip():
    return {"valid": False, "error": "...", "fix_hint": "..."}

# Gate 2: role 必须是 manager/worker/reviewer
if role not in {"manager", "worker", "reviewer"}:
    return {"valid": False, "error": "...", "fix_hint": "..."}

# Gate 3: task 必须存在
row = conn.execute("SELECT ... WHERE task_id=?", (task_id,)).fetchone()
if not row:
    return {"valid": False, "error": "...", "fix_hint": "..."}
```

### 2. a2a_server.py — SSE + 友好错误响应

- 检查 `result.valid`，失败时返回 HTTP 422 + `{ok: false, error, fix_hint, example}`
- 成功时 emit SSE `message_added` 事件

### 3. watchdog_sse.py — ACP 消息投递

`_handle_message_delivery()`:
1. 从 a2a_tasks 查 raw_key
2. 从 agent_working 查 session
3. 通过 ACP session/prompt 投递消息到正确 bridge (opencode/claude/cline)

### 4. a2a_task.py — CLI 友好输出

`update_message()` 失败时打印 error + fix_hint + example 到 stderr。

## 残余风险
- SSE 连接断开时消息可能丢失（SSE 本身是 at-most-once）
- ACP bridge 不在线时投递失败（已有 liveness check）
