## 实现

- `freely`：新增 `project_start_lock_dir_age_secs_for_runtime()`（目录 age，`stat -f %m` / `stat -c %Y` 双平台）与 `project_start_lock_pid_belongs_to_project_for_runtime()`（cmdline 校验，读不到时保守返回「属于」，永不误杀活锁）。
- `acquire_project_start_lock_or_wait` 的 `state_file_missing` 分支：**先判 age**。`age < stale_secs` 视为「对方正在 `mkdir`→写 `state.env` 的窗口内」，继续等待（记 `project_start_lock_waiting` 事件）；只有 `age >= stale_secs` 且无活跃进程才回收。这条堵死了「两个 supervisor 都过门禁」的 TOCTOU。
- `project_start_lock_snapshot_for_runtime`：`kill -0` 成功后再验 cmdline；pid 活着但 command line 明确不含 `freely` → 判 `stale`（`owner_pid_reused`），不再白等 30s 超时。
- `freely_db_manager.py`：`import fcntl`；`cmd_start` 在 **fork 之前** `flock(LOCK_EX|LOCK_NB)` 抢 pid 文件，抢不到直接返回 0（已有实例）；锁 fd 由 forked child 继承，pid 写入走同一 handle，保证「记录的 pid」与「持锁进程」永不背离。
- `DbDaemon._existing_daemon_alive()`：`bind` 前先 `connect()` 探测；有存活 daemon 就拒绝 bind，不再 `unlink` 别人的 socket。
- `_cleanup`：删除 pid/socket 前比对 pid 文件内容 == 自己，孤儿 daemon 退出不再删健康 daemon 的文件。

## 不退化边界

- 不改锁的持有语义（仍是「启动窗口互斥」，未把 fd 继承给 supervisor——那会改变 stop/restart 语义）。
- 不改 `freely start` 的对外行为：已有实例仍返回 0（幂等），只是不再可能重复起。
- 保留 `active-but-stalled`（age ≥ stale_secs 且无活跃进程）的既有回收路径。
- `ps` 不可读（受限环境）时 cmdline 校验退化为保守判断，不会误杀活锁。
