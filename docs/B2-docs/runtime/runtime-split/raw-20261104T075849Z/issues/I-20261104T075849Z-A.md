## 根因

`scripts/runtime/freely` 已从 issue 记录的 26,823 行涨到 **27,272 行**，而
`bin/check-file-size` 对它带 `# file-size: skip` 标记、完全跳过，所以「不再增长」
这条承诺此前没有任何机制。同时 56 个 `cmd_*` 里只有 12 个已按 `exec bin/<cmd>`
外移，其余仍内联在单体中。

外移的真实阻塞不是「写个 bin 文件」，而是：这些命令依赖 `log_error`、
`run_dir_for_project`、`current_timestamp_utc_for_machine` 等内联 helper，
抽出后只能复制（漂移）或 source 单体（循环）。

## 修复方案

1. 新增 `scripts/runtime/lib/common.sh` 作为 helper 唯一 owner：`_log_ts`、
   `log_info/warn/error`、`current_timestamp_utc_for_machine`、`state_dir`、
   `run_dir_for_project`；单体改为「守卫式 source」并删掉内联定义。
2. 外移 3 个子命令到 `bin/`：`cmd_test_gate_run` / `cmd_test_gate_record` → `bin/test-gate`，
   `cmd_evidence_add` → `bin/evidence`；`_test_gate_file` / `_test_gate_write` 一并移入；
   单体只留 `exec bash "$SELF_ROOT/bin/..."` 投影。
3. 新增 `bin/check-runtime-size` + `runtime/.size-budget`：超过预算 fail-closed，
   预算只许下调。
4. 新增 `runtime/split-plan.md`（56 个 `cmd_*` 的依赖矩阵 + 4 阶段拆分顺序，脚本生成）
   与 `runtime/rust-migration-poc.md`（边界/成本/回滚，明确未迁移）。
5. AT-001 12 静态 + 4 行为；`tests/unit/t-runtime-split-01.sh` 24 断言；进 `CORE`/`CI_CORE`；
   `epic-runtime` 注册 `runtime-split` story。

## 验收标准

- RED：develop `d33855eb0` + 最终版 AT-001 → `0 ok / 16 failed`。
- GREEN：工位同一断言 → `16 ok / 0 failed`；单测 16 文件 98 断言；`test-all --ci` 19/0；epics 17/214。
- GREEN：单体 27,272 → **27,158 行**，预算 27,158，`bin/check-runtime-size` → `ok`。
- 不退化：`bin/freely` 仍可执行 + 可 source；4 个 source 单体的脚本不受影响；
  既有 AT 全绿（R27 21、R28 21、R28.5 18、R29 16、R30 17）。

## 附带修复（吃狗粮抓到）

- 给 `bin/test-all` 前置插入新 AT 后，R30 的 `test-cross-process-contract.py` 立刻变红：
  它断言自身是 `CORE=(` 的**第一行**。已改为数组成员判定，两个 AT 共用 `array_has()`。

## 刻意不做（后续轮次）

phase 2/3 的 35 个命令、daemon/supervisor/dispatch 外移、任何 Rust 代码 —— 见
`split-plan.md` 的阶段判据与 `rust-migration-poc.md` 的下一步。
