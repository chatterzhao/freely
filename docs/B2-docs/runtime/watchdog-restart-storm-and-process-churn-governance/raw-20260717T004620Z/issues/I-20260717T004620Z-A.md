# I-20260717T004620Z-A: supervisor 生死判定一体收口

- source_candidate: docs/B1-docs/raw-20260717T004620Z/candidates.md#C-20260717T004620Z-A

## 问题

2026-07-16 全天 493 次 supervisor_cleanup、三次 restart storm、runtime 不可用约 9 小时。根因四面（B2 阶段核实新增第四面 C1c）：

1. **C1**：`ensure_manager_once` 对「heartbeat 文件存在但 stale」无新生宽限，heartbeat touch 子进程又在 bridge init 之后才启动（10-15s 裸奔窗口）→ stale heartbeat 遗留时每个新 supervisor 都被处决
2. **C1c**（B2 新核实）：`trap cleanup_supervisor EXIT`（L22340）被 heartbeat 块的 `trap 'kill $_heartbeat_bg_pid' EXIT`（L22509）覆盖 → 活过该点的 supervisor 退出时 cleanup 不执行
3. **C2**：heartbeat 判死用裸 TERM，而 daemon supervisor 有意忽略裸 TERM → 误信已杀死 → 拉第二个 daemon → 双 supervisor
4. **C4**：storm window 只在 AI 周期完成后记录（supervisor 死亡零计数）；PROCESS_CHURN_PEAK=10 超出计数口径上限 3 恒不可达；RESTART_STORM_COUNT 后备值 4 与 config 10 不一致

## 实现（详见 brainstorms/b-I-20260717T004620Z-A.md）

- C1-fix-1：stale 分支先比 sup_pid_file 与 heartbeat mtime，新生者按 `SUPERVISOR_STARTUP_HEARTBEAT_GRACE_SECS`（默认 15）宽限
- C1-fix-2 + C1c-fix：heartbeat 子进程块上移到 trap 安装后立即启动；EXIT trap 合并为单 handler（kill heartbeat + cleanup_supervisor）
- C2-fix：判死动作改走 `restart_manager_supervisor_preserving_handoff` + kill -0 验证消亡；不可杀时记事件并放弃本 tick 拉新
- C4-fix：ensure-manager 侧新增 supervisor 死亡的 storm window 记录；PROCESS_CHURN_PEAK 默认 10→3；RESTART_STORM_COUNT 后备值 4→10

## 边界（non-goals）

不改 supervisor 对 TERM 的忽略语义（raw-20260711T100936Z 既有设计）；不改 bridge 生命周期（raw-20260717T004654Z）；不改 sse pid 校验（raw-20260717T004721Z）；不改 stall 判定（raw-20260716T114802Z）。
