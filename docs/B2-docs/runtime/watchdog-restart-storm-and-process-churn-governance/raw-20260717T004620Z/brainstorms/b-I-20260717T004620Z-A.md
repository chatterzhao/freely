# b-I-20260717T004620Z-A: supervisor 生死判定一体收口 — 实现设计

根因证据链已在 B1 brainstorms.md 完成三源交叉验证（事件日志 / lifecycle trace / 两次受控重启实验），acceptance review 9/9 代码断言核验通过。

## 实现方案（逐缺陷）

### C1 — heartbeat 新生宽限（两处改动，双保险）

**C1-fix-1**：`ensure_manager_once` 的 heartbeat 检查块（~L19224-19251）。
现状：`[[ -f $_hb_file ]]` 分支只比较 `now - _hb_epoch > timeout`。
改法：stale 判定前先取 `sup_pid_file` mtime；若 `sup_mtime > _hb_epoch`（heartbeat 是上代遗留，supervisor 是新生），改用缺失分支同款逻辑：`now - sup_mtime > 15`（复用现有 15s 基准，抽成 `SUPERVISOR_STARTUP_HEARTBEAT_GRACE_SECS` 可配）才判 stale。语义：新生 supervisor 的活性以它自己的出生时间起算，不背上代的 stale 债。

**C1-fix-2**：heartbeat 子进程启动块（~L22491-22507）整体上移到 supervisor 启动序列早段——`trap cleanup_supervisor EXIT` 与 TERM trap 安装之后、`exit_if_stop_requested_before_launch` 之前。裸奔窗口从 10-15s（doc gate + bridge init 之后）压缩到 <1s。上移安全性：子进程只依赖 `_update_heartbeat`/`_rotate_log`/`$PROJECT_ROOT`/`$$`，均在该位置已可用；EXIT trap 对 `_heartbeat_bg_pid` 的清理 trap 需与 cleanup_supervisor 合并声明（bash 同信号 trap 后写覆盖前写，现状 L22508 的 `trap 'kill $_heartbeat_bg_pid' EXIT` 本就覆盖了 L22343 的 `trap cleanup_supervisor EXIT`——**这是现状 bug 的潜在第四面**，实现时必须让 EXIT trap 同时做两件事，否则上移后 cleanup_supervisor 失效）。

> 上移后原位置不再重复启动第二个心跳子进程。

### C2 — kill 通道语义（一处改动）

`ensure_manager_once` heartbeat 判死后的动作（~L19252-19255）现状：`kill "$current_pid"; sleep 1; current_pid=""`。
改法：调 `restart_manager_supervisor_preserving_handoff "$project"`（既有函数，含 `terminate_pid_with_graceful_wait`：TERM→50×0.1s 等待→KILL -9 兜底 + 清 pid/identity + 等待退出循环 L18924-18947）；随后**验证** `kill -0` 确认进程消亡才置 `current_pid=""`；若进程仍存活（不可杀），记 runtime event `manager_watchdog_supervisor_kill_failed` 并本 tick 放弃拉新（return 0），避免双 daemon。

### C4 — storm 观测（吸收 reviewer 建议：ensure-manager 侧记录，不在 dying process EXIT trap 里写）

**C4-fix-1**：新增小函数 `record_supervisor_death_for_storm_window(project)`——在 **ensure-manager 侧**（`ensure_manager_once` 发现 supervisor 死亡/完成 teardown 的两个入口）调用 `update_restart_storm_window`，而不是在 `cleanup_supervisor`（EXIT trap 信号上下文写文件不可靠，reviewer non-blocking #2）。同时保留 AI 周期完成处的现有调用（L23069）。
**C4-fix-2**：`PROCESS_CHURN_PEAK` config init 默认 10 → 3（计数口径 supervisor+dispatcher+ai 上限 3，peak=3 表示三类进程同窗全出现过重启，语义成立且可达）。
**C4-fix-3**：`restart_storm_signal_reason_for_window` 后备值 `RESTART_STORM_COUNT:-4` → `:-10`，与 config init（L4397）统一。

## 替代方案评估

- C1 只做 fix-1 不做 fix-2：窗口仍存在（若 heartbeat 文件被外部删除→走缺失分支 15s 宽限，但 bridge init 可能 >15s）→ 双保险成本低（代码块搬移），保留。
- C2 改成"supervisor 响应裸 TERM"：违反 raw-20260711T100936Z 已合并的设计（daemon 忽略裸 TERM 以区分 operator stop），不动 supervisor 侧，只改 watchdog 侧动作。
- C4 扩大进程计数口径（数 bridge/watchdog 等）：影响面大且与 bridge 泄漏 lane（raw-20260717T004654Z）耦合，不做；取降默认值。
