## 最终字段边界

合同最终固定为 21 个有序字段，顺序由 `RAW_METADATA_FIELDS` 定义：

```text
schema_version → local_id → kind → phase_state → absorbed_into
→ platform_ids → primary_platform → canonical_issue_path
→ last_synced_comment_at → hash → created_at → updated_at
→ intake_id → author → channel → session_refs → platform_state
→ promoted_children → source_candidate → completed_at → closeout_note
```

`closed_at`、`closeout_reason`、`force_closed_*` 没有稳定 writer/reader 证据且与 `wt-close` 零写入职责冲突，不进入合同。linked `I-*` metadata 也不混入 raw schema。

## 状态迁移


## PR 更新顺序

```text
preflight governance
→ observe every configured platform
→ fail closed on ahead/diverged/error/unsupported
→ controlled push for absent/behind
→ ensure PR for every platform
→ merge dry-run against synchronized heads
```

实现已按此顺序收敛：所有配置平台先完成五态观测，任一不安全状态在副作用前整体阻断；安全集合通过 adapter 受控同步并 ensure PR，最后才运行 merge dry-run。RED/GREEN 用例锁定调用顺序、全平台聚合和重试幂等性。
