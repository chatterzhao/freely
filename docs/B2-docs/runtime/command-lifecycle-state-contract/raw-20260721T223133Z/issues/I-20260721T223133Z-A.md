# I-20260721T223133Z-A：统一生命周期命令的受控更新与 raw 元数据状态合同

## 问题陈述

生命周期命令当前存在两个同源缺陷：命令在没有形成完整状态观测时直接执行或拒绝状态迁移。

1. 已有 PR 的本地分支领先平台远端时，`pr-create-guarded` 先调用要求等头的 merge dry-run，受控 push 永远无法执行。
2. `wt-create` 把“工位已创建”错误解释为“raw 已被 canonical B2 issue 吸收”，生成 `absorbed` 但无 `absorbed_into` 的非法组合。
3. raw metadata 由多个脚本各自维护字段，消费者同时存在按值、按键存在性和旧 `status` 判断三套语义。

## 能力边界

### A. 多平台 existing-PR 更新

```text
configured platforms
  → observe local/remote branch relation per platform
  → classify absent | behind | equal | ahead | diverged
  → controlled push only for absent/behind
  → create/reuse/update PR per platform
  → require every configured platform to reach success
  → run merge dry-run against synchronized heads
```

- 平台集合只来自 adapter/config registry，不写死 GitHub、Gitee 或 remote 名。
- `ahead` 与 `diverged` 必须 fail closed；恢复说明只能引用 Freely/adapter 路径。
- `created`、`updated`、`reused` 均是 PR 成功终态；配置平台的 `skipped` 不是成功。
- 真正 merge 继续要求本地与平台 source head 相等，不降低保护强度。

### B. 新 raw 的固定 metadata 合同

新 schema 使用固定扁平字段和固定顺序。生产者一次性初始化字段全集，后续命令只能替换值。

```text
schema_version
local_id
kind
phase_state
absorbed_into
platform_ids
primary_platform
canonical_issue_path
last_synced_comment_at
hash
created_at
updated_at
intake_id
author
channel
session_refs
platform_state
promoted_children
source_candidate
completed_at
closeout_note
```

字段含义：

- `schema_version`: 新合同版本；存在且等于当前版本时启用严格校验。
- `phase_state`: `proposed | absorbed | dropped`。
- `absorbed_into`: 仅 `absorbed` 非空，值为 canonical `I-*` ID。
- `canonical_issue_path`: `absorbed` 时指向对应 B2 issue；其他状态为空。
- `platform_state`: 平台聚合生命周期，`open | closed`。
- `platform_ids`: 配置平台引用映射；每个已创建平台包含非空 `issue_id`、`url`、`synced_at`。
- `promoted_children`: `promote` 阶段追加的 `I-*` 子 issue 列表；此时 raw 仍为 `proposed`。
- `source_candidate`: promotion 可选记录的 B1 candidate 来源。
- `completed_at`: raw 进入 `absorbed` 或 `dropped` 时的终态时间。
- `closeout_note`: `dropped` 必须非空；`absorbed` 可记录收口说明。

### C. 状态迁移与消费者

```text
feedback/pull:     ∅ → proposed/open
wt-create:         proposed/open → proposed/open
promote(child):    proposed/open → proposed/open + promoted_children
promote-finalize:  proposed/open → absorbed/open + canonical relationship
platform close:    absorbed|dropped/open → same phase/closed
manual drop:       proposed/open → dropped/open → dropped/closed
```

每次迁移原子写入关联值；禁止单字段制造中间非法状态。scan/gate/sync/PR/closeout 通过共享解析器读取 normalized view：

- 新 schema：字段全集、顺序、类型、枚举和跨字段组合严格校验，失败即关闭门禁。
- legacy：允许缺少新字段并归一化旧 `status`，不自动重写；若声称 `absorbed` 却无法解析目标，涉及 PR/merge 的危险操作仍 fail closed。

## 合法组合

| phase_state | absorbed_into / canonical_issue_path | completed_at | closeout_note |
|---|---|---|---|
| proposed | 均为空 | 空 | 空 |
| absorbed | 至少一个可验证；非空 ID 必须为 `I-*`，路径必须为项目相对路径 | 非空 | 可空 |
| dropped | 均为空 | 非空 | 非空 |

`platform_state` 独立取 `open | closed`；平台关闭不改变 raw phase，也不负责推导 absorption。

## 职责分配

- 共享 metadata 模块：schema、顺序、默认值、解析、序列化、校验与迁移。
- 平台 adapter：配置平台发现、远端观测、受控 push、PR create/reuse/update。
- `feedback` / `raw-issue-pull`：建立相同的新 schema 初态。
- `wt-create`：创建工位，不改变 raw lifecycle。
- B1/B2 promotion：`promote` 只登记 1:N children；`promote-finalize` 是唯一 `proposed → absorbed` 入口。
- `issue-sync close`：在 raw 已为 `absorbed|dropped` 后记录平台关闭；不推导 phase。
- `wt-close`：只清理工位/分支并调用配置平台 adapter，metadata 与治理文档零写入。
- scan/gate/PR/closeout：只消费共享模块提供的语义状态，不自行拼字段条件；scanner 只报告、不修复。

## 不在范围

- 不批量重写历史 751 份 raw issue。
- 不支持 raw Git push 或平台 CLI 绕过。
- 不把多平台“任一成功”视为整体成功。
- 不在本变更中清理全部历史冲突标记或脏 metadata；仅保证兼容读取与危险操作 fail closed。

## 验收标准

1. 本地领先已有 PR head 时，所有配置平台完成 adapter-controlled push，并复用或更新现有 PR。
2. absent/behind/equal/ahead/diverged 五态均有确定、可测试动作。
3. 任一配置平台失败、ahead、diverged 或 unsupported，整体失败且输出逐平台结果。
4. 新 raw 首次本地物化即具有固定字段全集、顺序和显式初值。
5. `wt-create` 后仍为 `proposed`，且 metadata 字段集合与顺序不变。
6. promotion 原子形成 `absorbed + absorbed_into + canonical_issue_path`；非法组合被 scan/gate 拒绝。
7. legacy raw 保持可读且不被隐式批量迁移。
8. RED/GREEN 证据覆盖单元、集成、预合并与真实 existing-PR 更新场景。
