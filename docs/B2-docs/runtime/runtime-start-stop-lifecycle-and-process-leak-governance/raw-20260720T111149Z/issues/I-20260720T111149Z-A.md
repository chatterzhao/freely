# I-20260720T111149Z-A: DB daemon 存活监控与 task-mode 查询降级修正

## Summary

修复 freely-db daemon 无声退出导致 task-mode 查询降级为 wait（伪装成权威值）的三层缺陷：

1. **read_task_mode**: DB 查询全部失败时返回 `error:db_unavailable` + 退出码 1（不再伪装成 wait + 退出码 0）
2. **Supervisor 主循环**: 读 task-mode 前检查 DB daemon 存活，不可用时重启或写 `db_unavailable` workcell-state
3. **ensure_freely_db**: 增强可重入性，处理 stale PID 文件
4. **freely_db_manager.py**: 崩溃时写 FATAL traceback 到 db-daemon.log

## Changes

### File 1: `docs/system/workspace/scripts/runtime/freely`

#### A. read_task_mode (L8793-8794): 错误语义修正
- 三重重试失败后输出 `error:db_unavailable` 并返回 1（非零退出码），不再返回 `wait` + 退出码 0
- 所有 6 个调用方兼容性已验证：要么有 DB health gate 保护，要么不匹配 `error:db_unavailable` case 安全跳过

#### B. Supervisor 主循环 (L22958 前): DB health gate
- 每次读 task-mode 前调用 `ensure_freely_db "$PROJECT_ROOT"`
- 失败时写 workcell-state `error/up/down/db_unavailable`，sleep 5，continue
- 防止 Supervisor 在 DB 盲区中继续驱动 AI

#### C. ensure_freely_db (L8639 后): stale PID 处理
- 检查 PID 文件对应进程是否存活
- 进程已死 → 清理 PID 文件和 socket → 重新启动

### File 2: `docs/system/workspace/scripts/runtime/freely_db_manager.py`

#### D. start(): 崩溃日志防御 (L426-431)
- `start()` 方法外层包 try/except，崩溃前写 FATAL traceback
- `_cleanup` signal handler 新增日志：收到信号时写 "daemon received signal {sig}, stopping"
