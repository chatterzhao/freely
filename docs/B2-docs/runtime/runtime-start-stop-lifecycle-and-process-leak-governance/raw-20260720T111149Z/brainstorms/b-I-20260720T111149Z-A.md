### 改动 1: read_task_mode 故障语义修正 (freely L8785-8803)

**当前行为**:
```bash
if [[ -z "$result" ]]; then
    log_error "task_mode degraded to WAIT..."
    echo 'wait'; return 0  # ← BUG: 退出码 0，输出 wait
fi
```

**修复后**:
```bash
if [[ -z "$result" ]]; then
    log_error "task_mode DB query failed after 3 retries (freely-db daemon not ready or crashed)"
    echo 'error:db_unavailable'; return 1  # 非零退出码 + 错误 token
fi
```

**调用方兼容性分析**:
| 调用点 | 行号 | 当前用法 | 修复后行为 |
|--------|------|---------|-----------|
| `task-mode get` CLI | L936/L17758 | `read_task_mode "$PROJECT_ROOT"` 输出到 stdout | 输出 `error:db_unavailable`，退出码 1 → CLI 显示错误 |
| `_manager_auto_consume_workers` | L16209 | `_tm_mode="$(read_task_mode "$project")"` → case match | `error:db_unavailable` 不匹配任何 case (auto/id:/wait/listen)，安全跳过 |
| `manager_runtime_handle_exit_contract_after_ai_cycle` gate | L16293/L16336 | `read_task_mode "$project"` | 同上，不匹配 auto → 不进入 auto→listen 逻辑 |
| Supervisor main loop pre-gate | L22961 | `_pre_tm="$(read_task_mode "$PROJECT_ROOT")"` | 修复 2 在此检查前插入 DB health gate，所以不会再盲读 |

| Manager backlog check | L20660 | `read_task_mode "$PROJECT_ROOT"` | 同上 |

所有调用方要么有修复 2 保护，要么安全跳过 `error:db_unavailable` 不匹配的 case 分支。无需额外改动。

### 改动 2: Supervisor 主循环加 DB health gate (freely ~L22959 前)

在 `read_task_mode` 前插入 `ensure_freely_db` 调用：

```bash
# DB health gate: ensure freely-db is alive before reading task mode
if ! ensure_freely_db "$PROJECT_ROOT"; then
  log_error "freely-db daemon unreachable and restart failed; control plane degraded"
  write_workcell_state "$PROJECT_ROOT" "error" "up" "down" "db_unavailable"
  sleep 5
  continue
fi
```

连续失败时 workcell-state 反映真实故障状态，sleep 5 防止 CPU 空转。

### 改动 3: ensure_freely_db 可重入 (freely L8633-8665)

当前 `ensure_freely_db` 已经支持可重入：
1. L8640: 先 `db.ping` → 成功则 return 0
2. L8644-8650: 失败则启动 daemon
3. L8652-8661: 等待就绪（最多 5 秒）

**需要增强**：daemon PID 还在但 socket 无响应时（stale PID 场景），应先 kill 旧 PID 再重启。

```bash
ensure_freely_db() {
  # ... existing ping check ...
  
  # Stale PID check: PID file exists but process dead
  local pid_file; pid_file="/tmp/freely-db-$(python3 -c "
import hashlib,os
h=hashlib.sha256(os.path.abspath('$project').encode()).hexdigest()[:16]
print(h)" 2>/dev/null || true).pid"
  if [[ -f "$pid_file" ]]; then
    local old_pid; old_pid=$(cat "$pid_file" 2>/dev/null || true)
    if [[ -n "$old_pid" ]] && ! kill -0 "$old_pid" 2>/dev/null; then
      log_warn "stale freely-db PID $old_pid (process gone), cleaning up"
      rm -f "$pid_file"
      rm -f "/tmp/freely-db-$(...).sock"
    fi
  fi
  
  # ... existing start logic ...
}
```

### 改动 4: DB daemon 崩溃日志防御 (freely_db_manager.py L426-431)

```python
def start(self) -> None:
    try:
        self._open_db()
        self._ensure_tables()
        self.running = True
        self.uptime = time.time()
        self._run_socket_server()
    except Exception as e:
        import traceback
        self.log(f"FATAL: daemon crashed with {type(e).__name__}: {e}")
        self.log(traceback.format_exc())
        raise
```

`_cleanup` signal handler 也加一行 log："daemon received signal {sig}, stopping"，确保信号触发的退出也有日志。
