## 输入

## 方案确认（对 B1 Decision Option B 的实现细化）

### 1. db_manager 列名修复（P4 根因）
`h_aw_get` / `h_aw_get_all` 两处 `cols = [d[0] for d in PRAGMA table_info(agent_working)]` → `d[1]`。
- 依据：`PRAGMA table_info` 返回 `(cid, name, type, notnull, dflt_value, pk)`，列名在下标 1；同文件 a2a_tasks 六个 handler 全部用 `desc[1]`，本修复即对齐既有写法。
- 消费面核查：全仓 grep 无任何数字键消费者；命名键消费者 8 处（watchdog_sse×3、pr-review-guarded×2、task-lifecycle-scan、wt-close teardown、gate）。修复即全面恢复，无兼容性断裂。
- 附带效果：watchdog_sse 的 worker/reviewer 复用路径（`row.get("worker_id")` 判已有分配）自此真正生效——此前恒 None 走 agent_next_free 重新分配。

### 2. gate 韧性（P1/P2 根因）
- heredoc 内 try/except 全包裹 + 赋值 `|| true`：db daemon 不在（socket 缺失）= runtime 未跑 = 无活跃 agent → 空值降级，gate 继续判定，**永不静默杀死 wt-close**。
- `_main_root=$(dirname "$(git -C "$PROJECT_ROOT" rev-parse --path-format=absolute --git-common-dir)")`：工位内 git-common-dir 指向主仓 `.git`，取其父目录即主仓根；失败回退 `$PROJECT_ROOT`。agent_working socket（按根 hash）、a2a db、B1 phase_state 全部改经 `_main_root` / develop 权威版（`git show develop:docs/B1-docs/...`）。

### 3. _has_merge 免管道（P3 根因）
`git rev-list develop --merges --grep "raw-${key}" --count`：单命令无管道，SIGPIPE 竞态不存在；`--merges` 精确过滤 merge commit，语义比原"oneline+正则"更强。

### 4. usage 同步
`--force` 描述已更新为"绕过自治门禁的拒绝判定（unfinished/foreign block）……正常自治关闭不需要此标志"。

## 边界

- 不改 agent_working.py 客户端、不改 watchdog_sse（它们因 handler 修复自动恢复）。
- 不改 gate 判定矩阵语义（PR #3980 已定）：只修判定的三条输入通道。
- 主 db daemon 需在合并后重启才载入 handler 修复（随 runtime 整体重启一并做）。
