# B2 Brainstorm: task_mode propagation fix
- issue_id: I-20260714T021808Z-A

## Implementation Analysis

### Change Surface

4 处代码修改，均在 `docs/system/workspace/scripts/runtime/freely`：

**A. task_mode 传递链（3 处）：**
1. `launch_project_runtime_daemon_or_fail` (L23480): 增加 `$2` task_mode → Python spawn 命令行加 `--task-mode`
2. `cmd_daemon_start` (L23642): 调用时传 `$task_mode`
3. `start_project_runtime` (L22003): 增加 `$3` task_mode，替换 hardcode `"wait"`

**B. watchdog 重启（1 处）：**
4. `launch_manager_supervisor` (L18254): 允许列表加 `listen`，fallback 改 `wait`

**C. AI_MODE 守卫（3 处）：**
5. L22697: `$AI_MODE` → `${AI_MODE:-none}`
6. L22719: `$AI_MODE` → `${AI_MODE:-none}`
7. L24994: `${AI_MODE}` → `${AI_MODE:-none}`

### Alternatives Considered

- **Option A (全链路)**: 改动 4 个函数签名 → 放弃：改动面过大
- **Option B (仅 DB)**: 不传递 task_mode，读 DB → 放弃：违背"手工启动不准读DB"设计
- **Option C (最小链路)**: 只修必要断裂点 → 采用

### Risk Assessment

- `start_project_runtime` 有两处调用点 (`cmd_daemon_run` L23711 和 `cmd_start` L23400/23448)，需确保 worker 路径兼容
- Python spawn 在 `launch_project_runtime_daemon_or_fail` 中，增加参数需保证 shell quoting 正确
- `listen` 加入允许列表后 watchdog 重启行为与设计一致
