## 实现

- `runtime/freely::persist_execution_network_state` 去掉 4 键 heredoc，改 `python3 "$STATE_FILE_PY" write <path> --kv KEY=VALUE`（4 次），值经 argv 传递、落盘 `KEY<TAB>json.dumps(value)`。
- 两处读侧删掉 `source`：`execution_network_launch_block_active` 用单键命令替换 `values`；`runtime_network_failure_reason_from_log` 用 `{ read -r a || true; read -r b || true; } < <(python3 ... values ... || true)`（macOS bash 3.2 无 `mapfile`）。缺文件/失败回落 0，与原语义一致。
- 耦合回归 `test-freely-execution-network-failure-classification` 的 3 处 `grep -q '^KEY="value"$'` 改为 `read_state_value KEY`（走 `state_file.py values`），**语义不变、格式无关**。
- 逐族 AT 的 lint 计数断言由绝对数改为单调守卫：R23.11 的 `== 54` → `0 < got < 55`，本族 `== 52` → `0 < got < 54`。修掉「每迁一族就把上一族 AT 拖红」的固有缺陷。
- 新增 `docs/system/workspace/scripts/tests/test-state-family-execution-network.py`（AT-001，11 项，source 真实 `freely` 并调用真实函数）。

## 不退化边界

- 键名与语义不变（4 个 `EXECUTION_NETWORK_*`，下游判定逻辑未动）。
- 兼容旧 `KEY=value` 状态文件，不要求清空 `.freely/run/`。
- 未动其余 52 处状态 `source`、39 处非状态 `source`、`load_meta_env_snapshot`。
- 协议既有 `read` / `write --data` / `to-shell` / 白名单行为未改。
- `check-state-file-sources` 计数 **54 → 52**。

其余 52 处状态 source 与对应写入点按族逐轮推进；`manager_worker_launch`（14 读 / 11 键）、`workcell`（20 读）等大族待 #4264 补齐白名单后再迁。已排进 goal。
