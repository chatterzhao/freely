## 实现方案

B1 已决策：用 `meta_env_value` 替换 `source`。

### 改动点

`write_workcell_state()` 在 `docs/system/workspace/scripts/runtime/freely:8423-8428`：

```bash
# Before（unsafe）:
if [[ -z "$entrypoint_mode" && -f "$state_file" ]]; then
    unset LAST_ENTRYPOINT_MODE
    source "$state_file"
    entrypoint_mode="${LAST_ENTRYPOINT_MODE:-}"
fi

# After（safe）:
if [[ -z "$entrypoint_mode" && -f "$state_file" ]]; then
    entrypoint_mode="$(meta_env_value "$state_file" "LAST_ENTRYPOINT_MODE")"
    entrypoint_mode="${entrypoint_mode:-}"
fi
```

### 为什么安全

- `meta_env_value` 用 `awk -F '"'` 按双引号分割取值，不执行 shell
- heredoc 模板已经用 `KEY="value"` 格式写文件，与 `meta_env_value` 的解析约定一致
- 项目中 verification contract 读取等多处已使用 `meta_env_value`

### 附带修复

`.freely/run/workcell-state.env` 被错误提交到 git（`.gitignore` 已有 `.freely/` 规则）。执行 `git rm --cached` 移除跟踪。

## 边界

- 不改 `meta_env_value` 本身
- 不改其他 `source` env 文件的调用（本次 scope 仅限于 `write_workcell_state`）
- 不影响 heredoc 写入格式

## 替代方案评估

B1 中已评估 Option B（写入时转义）和 Option C（grep+cut），均因改动面大或一致性差被否决。
