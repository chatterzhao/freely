## 实现

- **四层 CAS**：`freely_db_manager.py::h_a2a_task_update` 支持可选 `expected_state`，用单条 `UPDATE ... WHERE task_id = ? AND state = ?` 完成原子抢占（沿用 R20 单写者边界）；`a2a/a2a_server.py` 的 `update_fields` 返回 affected，PATCH 对 `expected_state` 冲突返回 409 `state_conflict`，并支持 legacy `expected_status` 词表；`a2a_task.py` 登记 `--expected-state` / `--expected-status`（此前被 `parse_known_args()` 静默吞掉），透传并在冲突时输出 `conflict` 且 `sys.exit(3)`。
- **启动前抢占**：`runtime/freely` 的 `manager_runtime_launch_workers_after_ai_cycle_if_needed` 在创建 handoff record 与启动 worker **之前**执行 `submitted → working` CAS，失败即 `continue`（不再 `|| true` 吞掉）；删除启动后的 `--status "working"` 写。三处既有 `--expected-status pending` 调用第一次真正生效。
- **SSE 单实例所有权**：新增 `sse_watchdog_claim_pid`（`fcntl.flock` + 存活 pid + 可选 `ps` cmdline owner 校验，owner 不可验证时 fail-closed）；`sse-watchdog.sh` 与 `_start_watchdog_sse_py` 的 pid 写改走 claim，重复的 python watchdog 被 reaped；`cmd_ensure_sse_watchdog_watch` 改为监督循环，只经 `launch_sse_watchdog` 启动，不再写自身 `$$`、不再嵌套 `bash ... --watch`（watch-in-watch 死代码）。
- **CI 接线**：新增 `tests/test-dispatch-cas-sse-singleton.py`（AT-001，20 项），同时加入 `bin/test-all` 的 `CORE` / `CI_CORE`。

## 前置评审更正（重要）

1. 恢复点写「`--expected-status` 在 argparse 不存在，命令被拒」是**错的**：`a2a_task.py:847` 用 `parse_known_args()`，未知参数被静默丢弃，命令照常执行、状态照常改写，CAS 只是从未生效。这比命令失败更隐蔽。
2. issue 正文写「两个消费者同时向 manager 注入同一条 `state_update`」**不成立**：`watchdog_sse.py:164-182` 只处理 `input-required`，与 shell watchdog 的 `state_update` 注入职责互补。因此**没有删掉 python watchdog**，改为「监督者不消费、消费者只有一个」+ pid 互斥。照抄 issue 建议删消费者会丢掉 input-required 路由。

## 不退化边界

- 不改 R23.5（#4246）的 JSON Lines / NUL 流派发契约。
- 不改 R19（#4155）的启动锁与 DB daemon 单实例；不改 `|| true` 的其它容错语义（#4157/R25）。
- 不删 `sse-watchdog.sh` / `watchdog_sse.py` 的既有事件语义，只收敛实例数与 pid 所有权。
- 不改 A2A 六态状态机词表；`expected_state` 是可选前置条件，不传时行为与改前一致。
- 夹具不访问真实平台、不碰真实 `.freely/freely.db`、不派发真实 worker、不启动或杀死本机 watchdog。
