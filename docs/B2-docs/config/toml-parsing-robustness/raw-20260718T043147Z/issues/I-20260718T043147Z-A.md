# I-20260718T043147Z-A: config.toml 解析健壮性 — awk → 标准 TOML 解析器

- source_candidate: docs/B1-docs/raw-20260718T043147Z/candidates.md#C-20260718T043147Z-A
- pre_tests_path: docs/B2-docs/config/toml-parsing-robustness/raw-20260718T043147Z/verification/pre-tests.md
- verification_artifact_dir: docs/B2-docs/config/toml-parsing-robustness/raw-20260718T043147Z/code-reviews

## 根因

两层问题叠加导致 Worker ACP bridge 无法启动：

1. **协议层**：`opencode acp` 是 HTTP server，`acp-bridge.py` 使用 PTY+stdio JSON-RPC。协议不相交 → `initialize` 永远超时。
2. **配置解析层**（dev 阶段发现）：`monitor-ai-acp.sh` 用 awk 从 `config.toml` 手写解析取值，pattern 要求等号左侧恰好一个空格。TOML 规范允许等号两侧任意空格，手写 awk 无法覆盖所有变体，导致 ACP binary 路径可能静默读取失败。

前者是症状的直接原因（B1 已收敛），后者是系统性问题——全项目任何 shell 脚本中用 awk/sed/grep 手写解析 TOML 的地方都有同样的脆弱性。

## 修复

### 即时修复
`monitor-ai-acp.sh` awk pattern 改为容忍等号两侧空格。

### 根治
为 `freely_config.py` 新增 `get` 子命令，基于 Python 标准库 `tomllib.load()` 解析 `config.toml`。`monitor-ai-acp.sh` 的取值逻辑从 awk 改为调用 `freely_config.py get`。

```bash
# 改前（awk — 格式依赖）
config_path=$(awk -F'"' -v k="$config_key" '$1 == k " =" {print $2; exit}' "$project/.freely/config.toml")

# 改后（标准 TOML 解析 — 格式无关）
config_path=$("$SCRIPT_DIR/freely_config.py" get --project "$project" --key "$config_key")
```

## 验收标准

1. `freely_config.py get` 在 `=` 两侧有空格、无空格、不对称空格等 TOML 合法格式下均正确取值
2. `monitor-ai-acp.sh` 不再包含 awk 手写 TOML 解析逻辑
3. 全项目无其他 shell 脚本通过 awk/sed/grep 手写解析 `.toml` 文件（已审计确认仅此处）
