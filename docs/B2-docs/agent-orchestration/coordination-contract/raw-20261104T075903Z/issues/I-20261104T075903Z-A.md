## 根因

协调语义分散在协议类型、客户端、SSE 订阅、决策函数、理由枚举、角色配置六处，
没有任何机器可读契约；`watchdog_sse.py:16` 把 `agents/` 注入 `sys.path` 才能裸名
导入 `InputRequiredReason`，import 关系无法静态分析，新增 reason 容易漏改。

## 影响

- 新增 reason 或换通知机制要跨 6+ 文件，任一处漏改即静默漂移。
- `sys.path` hack 让包结构不可分析，外部项目无法只替换协调实现。
- exit contract 的合法值只存在于 `runtime/freely` 函数体里，无单页可查。

## 修复方案

1. `contracts/coordination/contract.yaml`（JSON 兼容 YAML 1.2 子集）：task_states / 12 个 reasons / SSE topics / exit_contracts + 每段真源标注。
2. `scripts/runtime/coordination/` 包承接枚举；删除 `agents/input_required_reason.py`。
3. `watchdog_sse.py` 删除 agents sys.path 行并改包导入；三个测试同步迁移 sys.path 与 import。
4. `bin/check-coordination-contract` 守护契约↔枚举一致、agents sys.path 为 0、import 方向、watchdog 导入形态（0/1/2）。
5. 单页文档 `contracts/coordination/README.md`；AT-001 进 CORE/CI_CORE；epics-map 注册 `coordination-contract` story。

## 验收标准

- RED：develop `90abdd4f4` + 最终版 AT-001 → `1 ok / 15 failed`。
- GREEN：工位同一断言 → `16 ok / 0 failed`；lint `ok (12 reasons)`；`test-all --ci` 17/0；epics-map 16/212。
- 不退化：a2a_types / a2a_server / a2a_task / `manager_exit_contract_kind` 逻辑逐字未动；workflow 全链路不变。
